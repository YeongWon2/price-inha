### 2-3. 새 사용 흐름

## <a id="f10"></a>F10 · 사무실에서 내 캐릭터로 다니며 담당과 이야기하기 · [R5](prd.md#r5)

쓰는 곳: [C17](dev.md#c17) · [C18](dev.md#c18) · [C20](dev.md#c20) · [E40](dev.md#e40) · [E41](dev.md#e41) · [E42](dev.md#e42) · [E43](dev.md#e43) · [E44](dev.md#e44) · [E47](dev.md#e47) · [E48](dev.md#e48) · [N9](dev.md#n9) · [N10](dev.md#n10) · [N11](dev.md#n11)

| 항목 | 내용 |
|---|---|
| 목적 | 내 캐릭터로 사무실을 걸어 다니며 담당에게 다가가 말을 걸거나, 멘션이나 부르기로 담당을 곁에 불러 이야기한다 |
| 행위자 | [P1](prd.md#p1) |
| 시작 | 사용자가 컴퓨터에서 사무실 화면을 연다 |
| 사전 조건 | 처음 설정을 마쳤다 |
| 기본 흐름 조건 | 담당이 가까이 있는가: 예, 담당이 회의 중인가: 아니오 |
| 성공 결과 | 담당과 이야기를 나누고 담당은 대화가 끝나면 자리로 돌아간다 |
| 실패 시 보장 | 이동과 대화가 실패해도 팀의 운용과 논의는 그대로 이어진다 |

### 기본 흐름

- 1. 사무실이 열리면 내 캐릭터가 마지막으로 있던 자리(없으면 입구)에 서고 카메라가 따라간다
- 2. 사용자가 방향키로 내 캐릭터를 움직인다
- 3. 담당 2칸 안에 들어가면 화면 아래에 "○○을(를) 클릭하거나 /를 눌러 대화"가 보인다
- 4. 사용자가 그 담당을 누르거나 /를 누른다
- 5. 그 담당과의 대화가 열린다
- 6. 사용자가 묻고 담당이 답한다([F7](#f7) 기본 흐름 5~6과 같다)
- 7. 사용자가 담당에게서 멀어지면 대화가 닫힌다

### 대안 흐름

- 2a. 사용자가 바닥을 누른다
  - 2a1. 내 캐릭터가 누른 곳까지 길을 찾아 걸어간다
  - 2a2. 3으로 돌아간다
- 2b. 사용자가 담당을 누른다(멀리 있다)
  - 2b1. 내 캐릭터가 그 담당 옆 빈 칸까지 걸어간다
  - 2b2. 5로 돌아간다
- 3a. 2칸 안에 담당이 둘 이상 있다
  - 3a1. /를 누르면 "누구와 대화?" 목록이 뜬다
  - 3a2. 사용자가 고른다
  - 3a3. 5로 돌아간다
- 4a. 사용자가 팀 방 채팅에 @를 치고 담당을 골라 보낸다(멘션이 있는가: 예)
  - 4a1. 멘션된 담당만 답을 쓰기 시작한다
  - 4a2. 답을 쓰기 시작하는 순간 그 담당이 내 곁으로 걸어온다
  - 4a3. 답은 채팅 패널과 머리 위 말풍선에 보이고 1:1 대화는 열리지 않는다
  - 4a4. 사용자가 팀 방을 보는 동안 그 담당은 곁에 남는다
  - 4a5. 사용자가 다른 방으로 바꾸면 그 담당은 바로 자리로 돌아간다
  - 4a6. 끝난다
- 4b. 사용자가 팀 방에 멘션 없이 보낸다(멘션이 있는가: 아니오, 공지로 보냈는가: 아니오)

## <a id="f11"></a>F11 · 팀 방 전체 공지 · [R17](prd.md#r17)

| 성공 결과 | 여섯 담당이 공지를 받았다는 확인 답이 채팅에 보이고 다음 논의의 자료에 공지가 들어간다 |

### 기본 흐름

- 1. 사용자가 공지 글을 쓰고 "공지로 보내기"를 누른다
- 2. 팀 방 채팅에 공지가 따로 눈에 띄는 모양으로 보인다
- 3. 공지가 내 컴퓨터의 기록에 "내가 쓴 것"으로 남는다
- 4. 여섯 담당의 공지 확인이 기다림이 된다
- 5. 담당마다 한 줄 확인 답을 쓰고 공지 확인이 답함으로 바뀐다
- 6. 다음 논의가 열리면 담당들의 자료에 공지가 들어간다

### 대안 흐름

- 1a. 글에 멘션이 있다
  - 1a1. "공지로 보내기"를 누를 수 없고 멘션 글로 보내진다([F10](#f10) 4a)
  - 1a2. 끝난다
- 4a. AI 호출이 넉넉한가: 정리 모드 또는 팀장 몫만
  - 4a1. 공지는 여섯 담당에게 전달되고 기록에 남는다
  - 4a2. 남은 호출(팀장 예비분 제외) 안에서만 확인 답을 쓴다
  - 4a3. 답하지 못한 담당은 공지 확인이 상한으로 못 함이 되고 채팅에 그렇게 보인다
  - 4a4. 6으로 돌아간다
- 6a. 공지가 지금 열린 논의 중에 왔다
  - 6a1. 진행 중인 논의는 그대로 이어지고 공지는 다음 논의부터 들어간다
  - 6a2. 끝난다

### 예외 흐름

- 1b. 공지 글이 규칙이나 승인이나 멈춤을 바꾸라고 한다
  - 1b1. 공지는 참고 글로만 남고 규칙과 템플릿 값과 승인과 팀 상태는 바뀌지 않는다
  - 1b2. 바꾸려면 해당 화면이나 승인을 거쳐야 한다는 안내가 보인다
  - 1b3. 5로 돌아간다

  - 5a2. 6으로 돌아간다

### 3-1. 결정 기록

#### <a id="d12"></a>D12 담당 부르기 · 멘션 걸어오기는 서버가 단계만 정하고 길은 화면이 찾는다

이유: 서버는 지도를 모르고 자리 이름만 보낸다(office 지시서). 원본 DeskRPG도 걷기는 브라우저가 계산하고 서버는 단계와 주인만 기록한다. 우리는 사용자가 한 명이라 "주인" 개념은 필요 없다. 서버는 자리 · 오는 중 · 곁에서 기다림 · 돌아가는 중 단계와 시각을 쥐고, 화면이 도착을 알린다.
버린 대안: 서버가 지도를 알고 길까지 계산하기(지도 자료를 서버에 들여야 하고 원본과도 다르다).
출처: [F10](spec.md#f10) › 대안 흐름 › 4c. 사용자가 담당 목록에서 "부르기"를 누른다

#### <a id="d13"></a>D13 근거 카드 칸은 담당 점수를 바꾸지 않고 옆에 더한다

이유: 잠긴 시험과 옛 매매를 지키려고 담당 점수(담당 · 점수 · 근거)는 그대로 두고, 방향 · 확신도 · 보는 기간 · 기권과 팀장 요약 · 뒤집힐 조건을 새 칸으로 붙인다. 옛 매매는 "기록 없음"이다. 확신도는 3등급(낮음 · 보통 · 높음)으로 둔다(투자 에이전트 팀 조사 F 1).
버린 대안: 점수 부호로 방향을 추정하기(기권과 중립을 가릴 수 없다).
출처: [R6-4](prd.md#r6-4)

#### <a id="d14"></a>D14 시연 모드는 자기 달력을 쓴다

이유: 시연용 가짜 증권사가 달력을 정하지 않아 늘 휴장이고 깨우기 엔진 첫 tick이 503으로 실패한다. 시연 달력은 매일을 거래일로 보고 시장 시간대 00:05~23:55를 정규장으로 둔다. 자정 앞뒤 10분은 장 밖이라 하루 시작 · 장 마감 뒤 일(하루 정리 · 복기 · 정산)이 매일 돈다. 시연 모드에서만 쓰고 실제 모드에서는 쓰지 않는다.
버린 대안: 늘 열림(장 마감 뒤 일이 돌지 않는다), 실제 장 시간(밤 시연에서 팀이 쉰다), 시연 단추로 장 마감 부르기(화면과 길이 하나 더 는다).

### 3-5. 오류 · 경계

#### <a id="e40"></a>E40 이동이 막힘

상황: 방향키나 바닥 누르기로 가려는 곳이 벽 · 가구 · 담당으로 막혔거나 길이 없다.
보이는 것: 내 캐릭터가 막힌 곳 앞에서 멈춘다. 길이 없는 곳을 누르면 움직이지 않는다.
시스템 처리: 그 프레임 이동을 0으로 하고 길 찾기는 정한 횟수에서 멈춘다([N9](#n9)).
출처: [F10](spec.md#f10) › 예외 흐름 › 2d

#### <a id="e41"></a>E41 글 쓰는 중 방향키

상황: 채팅 칸 · 입력 칸 · 고르기 칸에 글을 쓰는 중(한글 조합 중 포함)에 방향키를 누른다.
보이는 것: 글 칸의 커서만 움직이고 캐릭터는 그대로다.
시스템 처리: 이동 키를 무시하고, 창이 포커스를 잃으면 눌린 키를 모두 놓은 것으로 본다.
출처: [F10](spec.md#f10) › 예외 흐름 › 2c

#### <a id="e42"></a>E42 말 걸 담당이 없음 · 여럿

상황: /를 눌렀는데 2칸 안에 담당이 없거나 둘 이상이다.
보이는 것: 없으면 아무 일도 없다. 둘 이상이면 "누구와 대화?" 목록이 뜬다.
시스템 처리: 가까운 순으로 목록을 만든다.
출처: [F10](spec.md#f10) › 대안 흐름 › 3a

#### <a id="e43"></a>E43 멘션한 담당이 없음

상황: 보낸 글의 `@[이름]`이 담당 이름과 정확히 맞지 않는다.
보이는 것: 보낸 사용자에게만 "지목한 상대가 이 방에 없어 아무도 답하지 않았습니다."가 보인다.
시스템 처리: 아무 담당에게도 턴을 주지 않고 AI를 부르지 않는다.
출처: [F10](spec.md#f10) › 예외 흐름 › 4d

#### <a id="e44"></a>E44 멘션 없는 팀 방 글

상황: 팀 방에 멘션 없이, 공지도 아닌 글을 보낸다.
보이는 것: 글은 채팅에 남고 "@로 담당을 부르거나 공지로 보내세요" 안내가 보인다.
시스템 처리: 아무 담당도 답하지 않고 AI를 부르지 않는다(원본 DeskRPG 오피스 방과 같다).
출처: [F10](spec.md#f10) › 대안 흐름 › 4b

#### <a id="e45"></a>E45 공지 중 AI 호출 모자람

상황: 공지를 보냈는데 남은 호출(팀장 예비분 제외)이 6보다 적다.
보이는 것: 공지는 전달되고, 답하지 못한 담당은 "상한으로 답 못 함"으로 보인다.
시스템 처리: 남은 만큼만 확인 답 턴을 주고 팀장 예비분은 쓰지 않는다. 공지는 다음 논의 자료에 그대로 들어간다.
출처: [F11](spec.md#f11) › 대안 흐름 › 4a

#### <a id="e46"></a>E46 공지로 규칙 · 승인을 바꾸려 함

상황: 공지 글이 "손절을 넓혀", "승인해", "다시 시작해"처럼 규칙 · 승인 · 팀 상태를 바꾸라고 한다.
보이는 것: 확인 답 아래 "규칙 · 승인 · 멈춤은 해당 화면이나 승인으로만 바뀝니다" 안내가 보인다.
시스템 처리: 공지와 담당의 답은 승인으로 보지 않는다(P15 · P18 · P21). 규칙 · 템플릿 값 · 승인 결과 · 팀 상태를 바꾸는 길을 공지에 두지 않는다.
출처: [F11](spec.md#f11) › 예외 흐름 › 1b

#### <a id="e47"></a>E47 회의 중인 담당을 부름

상황: 부르거나 멘션한 담당이 지금 회의실 논의 중이다.
보이는 것: "○○은(는) 지금 회의 중이에요"가 보이고 담당은 걸어오지 않는다. 멘션이면 답은 채팅에만 온다.
시스템 처리: 부르기는 409 `meeting_reserved`로 거절하고 회의를 끊지 않는다.
출처: [F10](spec.md#f10) › 예외 흐름 › 4e

#### <a id="e48"></a>E48 부른 담당이 도착하지 못함

상황: 오는 중인데 화면이 닫히거나 도착 소식이 정한 시간 안에 오지 않는다.
보이는 것: 다시 열면 담당이 자리에 있다.
시스템 처리: [N10](#n10)의 시간이 지나면 돌아가는 중을 거쳐 자리로 둔다.
출처: [F10](spec.md#f10) › 예외 흐름 › 4f

#### <a id="e49"></a>E49 화면이 꺼진 동안 승인 요청

상황: 사무실 화면이 닫힌 동안 승인 요청이 생긴다.
보이는 것: 다시 열면 아직 기다리는 요청의 ✋ 말풍선이 보인다. 알림음은 다시 울리지 않는다.
시스템 처리: 첫 화면 자료에 기다리는 승인을 싣는다. 폰 알림은 지금처럼 간다([N5](#n5)).
출처: [FN2](spec.md#fn2) › 기본 흐름 › 1-1

#### <a id="e50"></a>E50 알림음을 낼 수 없음

상황: 브라우저가 사용자 동작 전이라 소리를 막았거나 사용자가 설정에서 껐다.
보이는 것: 소리 없이 ✋ 말풍선만 보인다.
시스템 처리: 사용자가 화면을 한 번 누른 뒤부터 소리를 낸다. 소리가 안 나도 승인 흐름은 그대로다.
출처: [FN2](spec.md#fn2) › 기본 흐름 › 1-1

#### <a id="e51"></a>E51 논의 중 담당 오류

상황: 논의 중 담당의 AI 부르기가 실패한다.
보이는 것: 그 담당이 "오류"로, 다시 시도 중이면 "다시 시도 n/3"으로 보인다.
시스템 처리: 3번까지 다시 시도하고, 그래도 안 되면 [E6](#e6)을 따른다.
출처: [F2](spec.md#f2) › 예외 흐름 › 5a

#### <a id="e52"></a>E52 하루 AI 호출이 상한에 가까움

상황: 남은 호출이 정리 모드 문턱이나 팀장 예비분까지 내려온다.
보이는 것: 잔량 바에 "정리 모드"가 보이고, 팀장 몫만 남으면 의견을 못 낸 담당이 기권으로 보인다.
시스템 처리: 정리 모드에서는 새 자료 가져오기와 더 말하기를 멈추고 지금까지로 의견을 내게 한다. 팀장 예비분은 다른 담당이 쓰지 않는다. 손절 · 청산은 규칙 엔진이 하므로 상한과 상관없이 계속된다(P2 · P11). 상한을 다 쓰면 지금처럼 그날 논의 · 깨우기를 쉬고 알린다.
출처: [F2](spec.md#f2) › 예외 흐름 › 5b

#### <a id="e53"></a>E53 근거 카드 빈 칸

상황: 의견 칸이 비었거나, 칸이 생기기 전 매매다.
보이는 것: 빈 칸은 "없음", 옛 매매는 "기록 없음", 기권은 0점과 다른 "기권"으로 보인다.
시스템 처리: 빈 칸을 추정해 채우지 않는다.
출처: [F7](spec.md#f7) › 기본 흐름 › 7

#### <a id="e54"></a>E54 정산할 시세가 없음

상황: 정산 날 종가를 받을 수 없다(거래정지 · 자료 오류).
보이는 것: 그 메모는 정산 대기로 남고, 정산 날에서 [N20](#n20)의 날수가 더 지나면 "정산 못 함(시세 없음)"이 된다.
시스템 처리: 정산 날까지 확정된 시세만 쓰고 판단 시각 뒤 자료로 앞을 채우지 않는다(P10).
출처: [F5](spec.md#f5) › 기본 흐름 › 0-2

#### <a id="e55"></a>E55 오래된 "일하는 중"

상황: 담당의 "일하는 중"이 300초 동안 새 소식 없이 남아 있거나, 늦게 온 옛 상태 이벤트가 있다.
보이는 것: 300초가 지나면 쉼으로 보인다. 옛 이벤트는 표시를 바꾸지 않는다.
시스템 처리: 상태 이벤트마다 단조 증가 시각을 붙이고 이미 본 것보다 옛 것은 버린다. 해제는 기록에 남긴다.
출처: [F7](spec.md#f7) › 예외 흐름 › 2a

#### <a id="e56"></a>E56 시연 달력이 실제로 새어 나감

상황: 실제 모드에서 시연 달력을 쓰려 하거나, 시연 모드에서 실제 증권사 · AI를 부르려 한다.
보이는 것: 없다(일어나면 안 된다).
시스템 처리: 시연 달력은 시연 어댑터 안에만 있고 실제 모드는 시장 어댑터 달력만 쓴다. 시연 모드는 모의계좌와 가짜 AI만 쓰고 바깥으로 나가는 요청을 만들지 않는다.
출처: [F1](spec.md#f1) › 대안 흐름 › 1c

#### <a id="e57"></a>E57 관리 화면 값을 못 받음

상황: 관리 화면이 서버에서 값을 받지 못한다(연결 끊김 · 서버 오류).
보이는 것: 그 칸에 "불러오지 못함 · 다시 시도"가 보이고 메뉴와 다른 칸은 그대로 쓴다.
시스템 처리: 실패한 요청만 다시 보낼 수 있게 하고, 받은 적 있는 값은 "마지막으로 받은 값"으로 함께 보인다.
출처: [F12](spec.md#f12) › 예외 흐름 › 1a

#### <a id="e58"></a>E58 화면에서 실전 운용 시작

상황: 템플릿 화면에서 "실전 운용 시작"을 누른다.
보이는 것: 승격대기가 아니면 단추가 막히고 모자란 기준이 보인다. 승격대기면 승인 요청이 생기고 "이 판에서는 실전 주문이 나가지 않는다"가 함께 보인다.
시스템 처리: 승격은 상태 · 승인까지만 잇고 실전 주문은 언제나 [E25](#e25)로 막는다(AGENTS 6번, 결정 2026-11-21 6번). 전체 정지 중에는 승격을 막는다.
출처: [F12](spec.md#f12) › 대안 흐름 › 2b

#### <a id="e59"></a>E59 두 화면에서 내 캐릭터

상황: 컴퓨터에서 사무실 화면을 두 개 연다.
보이는 것: 각 화면에서 내 캐릭터가 따로 움직인다. 다시 열면 마지막으로 저장된 자리에서 시작한다.
시스템 처리: 마지막에 온 자리 저장이 이긴다. 다른 화면에 내 위치를 중계하지 않는다.
출처: [F10](spec.md#f10) › 기본 흐름 › 1

#### <a id="e60"></a>E60 연출이 겹치거나 화면이 숨음

상황: 익절 · 손절이 잇따라 나거나 탭이 숨은 동안 난다.
보이는 것: 연출이 차례로 보인다. 숨은 동안 난 것은 건너뛰고 채팅 · 히스토리에는 남는다.
시스템 처리: 연출은 화면만의 일이고 매매 기록과 상관없다.
출처: [F4](spec.md#f4) › 기본 흐름 › 6-1

## 5. 기존 설계서와 부딪히는 곳

1. **office 지시서 "의도해서 다름: 사용자 캐릭터 없음"** (`docs/dev/modules/office.md` 머리말) ↔ [R5-4](#r5-4) 내 캐릭터. 사용자 결정(2026-11-25 "진짜 게임처럼")으로 바뀐다. 지시서의 그 줄을 지우고 결정 문서에 남긴다.
