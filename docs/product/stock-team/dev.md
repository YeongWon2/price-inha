# 주식 투자 에이전트 팀 개발 스펙

> 기준 문서: [기획 PRD](prd.md) · [기획 상세 스펙](spec.md) · [유저 플로우](flow.md) · [개발 스펙](dev.md)

## 결정 기록

### <a id="d1"></a>D1 서버는 Rust 한 프로그램으로 다시 만들고 3D 사무실 화면만 웹으로 둔다

이유: 메모리 문제 때문에 Python 에이전트 실행기와 Node 사무실 서버를 그대로 쓰지 않는다. 집 PC와 미니 PC에서도 24시간 가볍게 돌아야 한다.
버린 대안: Hermes Agent와 DeskRPG를 그대로 올려 확장하기, Hermes만 Rust로 바꾸기, 화면까지 Rust(WASM)로 만들기.
출처: 제약 › 집 PC, 노트북, 미니 PC의 모든 운영체제와 빌린 원격 컴퓨터에서 돌아야 한다.

### <a id="d2"></a>D2 기본은 그 컴퓨터에서만 열고 다른 기기는 접속 키로만 들어온다

이유: 본인만 쓰고 주로 로컬에서 쓴다. 밖에서 닿게 하는 길(Tailscale 등)은 사용자가 알아서 하므로 스펙에 넣지 않는다. Hermes와 OpenClaw의 기본값(자기 컴퓨터 주소에만 열기)과 같다.
버린 대안: Tailscale을 스펙에 넣기, OTP(인증 앱 6자리), VPN 켜고 끄기, 접속 키 없이 열기.
출처: 제약 › 나 혼자만 쓴다.

### <a id="d3"></a>D3 증권사 키와 AI 키는 Hermes 방식대로 홈 폴더의 파일에 본인만 읽는 권한으로 둔다

이유: API 키는 .env 파일에, 구독 OAuth 토큰은 auth.json에 0600 권한과 원자 쓰기로 둔다. 모든 운영체제와 원격 컴퓨터에서 같다. 화면과 기록과 AI 대화에는 다시 내보내지 않고 백업에서 뺀다.
버린 대안: OS 키체인(화면 없는 Linux에서 다르게 동작한다), DB에 저장, 백업에 포함.
출처: 제약 › 증권사 키와 AI 키는 내가 직접 등록한다.

### <a id="d4"></a>D4 AI는 Rust의 공급자 어댑터로 부른다. API 키는 직접 부르고, 구독은 공식 Claude Code CLI를 불러 쓴다

이유: API 키는 호출마다 프로세스를 띄우지 않아 빠르고 가볍다. 구독은 토큰을 우리가 쥐지 않고 사용자가 로그인한 공식 CLI에 맡긴다(구독 토큰을 다른 프로그램이 API에 직접 쓰는 것은 Anthropic이 금지). 각자 자기 컴퓨터에서 자기 AI 로그인을 세팅해 쓸 수 있다.
버린 대안: 구독 OAuth 토큰을 API 키와 같은 자리에 끼워 API에 직접 보내기(2026-11-15 사용자 결정으로 바꿈, `docs/dev/decisions.md`).
출처: 제약 › 각자 자기 컴퓨터에서 자기 로그인을 세팅해 쓸 수 있어야 한다.

### <a id="d5"></a>D5 시세와 주문과 장 시간과 시장별 원칙 값은 시장 어댑터로 나눈다

이유: 국내 주식과 미국 주식(토스증권)을 먼저 붙이고, 코인은 어댑터 하나를 더해 붙인다. 에이전트와 규칙 엔진은 시장을 몰라도 된다.
버린 대안: 지금은 주식에만 맞춰 만들고 코인 때 따로 설계하기.
출처: 제약 › 나중에 코인을 더할 수 있게 만든다.

### <a id="d6"></a>D6 상태와 매매 기록과 복기와 지식은 SQLite 파일 하나에 둔다

이유: 따로 설치할 것이 없고 모든 운영체제에서 같다. 전문 검색(FTS5)으로 기억을 찾고, 백업 API로 일관된 스냅샷을 뜬다.
버린 대안: PostgreSQL(따로 설치 · 운영하고 메모리를 더 쓴다).
출처: [D1](#d1)

### <a id="d7"></a>D7 매일 장 마감 뒤 SQLite 스냅샷을 age로 암호화해 private GitHub 저장소에 올린다

이유: 컴퓨터가 고장 나도 상태와 템플릿과 지식을 되살린다. 서버에는 공개키만 두고 푸는 열쇠는 GitHub 밖에 둔다.
버린 대안: 평문 private 저장소, git-crypt.
출처: [D6](#d6)

### <a id="d8"></a>D8 12월 최종 발표까지 [P1](prd.md#p1)과 P2 요구사항을 모두 돌아가게 한다

이유: 본인이 전부 12월까지 하기로 정했다.
버린 대안: [P1](prd.md#p1)과 모의투자만 먼저 하고 3D 사무실과 폰 화면은 발표에 필요한 만큼만.
출처: 제약 › 12월 최종 발표까지 나와야 한다.

### <a id="d10"></a>D10 지식은 에이전틱 RAG로 다루고, 키워드 · 조건 검색을 먼저 넣고 뜻 검색(벡터)은 공급자를 고른 뒤 붙인다

이유: 시세와 뉴스와 매매 기록은 실시간으로 많이 바뀌어 정리된 위키 페이지는 금방 낡는다. 담당이 판단할 때 검색 도구로 직접 찾는다. 키워드 검색과 조건 검색과 뜻 검색을 함께 쓰고, 임베딩은 AI 공급자 어댑터로 만들어 SQLite에 둔다. 승인된 규칙은 검색하지 않고 규칙 엔진의 확정값으로 둔다.
버린 대안: LLM 위키(에이전트가 페이지를 써서 유지).
바뀜 (2026-11-16, 사용자 결정): 원래는 "뜻 검색을 처음부터"였다. AI 공급자(Anthropic)가 임베딩을 주지 않아, 뜻 검색 자리(포트)만 먼저 두고 키워드 · 조건 검색부터 쓴다. 뜻 검색은 사용자가 임베딩 공급자를 고른 뒤 붙이고, 그 전에는 "쓸 수 없음"으로 돌려준다(`docs/dev/decisions.md` 2026-11-16 11번).
출처: [R8-1](prd.md#r8-1)

### <a id="d11"></a>D11 화면과 서버는 WebSocket 하나로 실시간을 주고받고 요청은 REST로 보낸다

이유: 채팅과 담당 움직임과 알림과 승인 요청을 한 연결로 받고, 끊기면 마지막으로 받은 번호부터 이어 받는다. 폰의 가벼운 화면과 3D 사무실이 같은 연결을 쓴다. 화면의 모든 요청은 접속 관문을 거친다.
버린 대안: SSE와 REST로 나누기, Socket.IO.
출처: [F7](spec.md#f7) › 대안 흐름 › 1a. 사용자가 폰에서 가격인하를 연다 › 1a2. 사용자가 3D 사무실을 누르면 사무실 화면이 열린다

### <a id="d9"></a>D9 재무 · 거시 · 뉴스 · 공시 자료는 공식으로 무료로 쓸 수 있는 API로만 가져온다

이유: 비용 없이 쓰고 출처가 분명해야 한다. 후보는 DART 오픈API(국내 공시 · 재무), 한국은행 ECOS와 미국 FRED(거시), SEC EDGAR(미국 공시 · 재무), 무료 뉴스 검색 API와 토스증권이 주는 자료다. 각 API 키는 본인이 등록한다.
버린 대안: 유료 데이터 서비스, 웹 페이지 긁어 오기, 토스 API 하나에만 기대기.
출처: [R12-2](prd.md#r12-2), [R12-3](prd.md#r12-3), [R12-4](prd.md#r12-4)

## 데이터 모델

### <a id="m1"></a>M1 투자 팀

| 값 | 뜻 | 규칙 |
|---|---|---|
| 상태 | 상태표의 투자 팀 상태 | 운용 중, 쉬는 중, 하루 한도 멈춤, 이상 감지 멈춤, 전체 정지 중 하나다 |
| 그날 손실 | 그날 실현 손실과 평가 손실 | 거래일마다 새로 센다 |
| 최고점 대비 손실 | 계좌 최고 평가액 대비 손실 | 템플릿 한도와 비교한다 |

- 전체 정지에서 다른 상태로는 내 승인으로만 바뀐다.
- 하루 한도 멈춤은 다음 거래일 시작 때만 풀린다.
- 상태가 바뀔 때마다 언제 왜 바뀌었는지 기록이 남는다.

출처: 기획 상세 스펙 › 상태표 › 투자 팀

### <a id="m2"></a>M2 매매

| 값 | 뜻 | 규칙 |
|---|---|---|
| 상태 | 상태표의 매매 상태 | 논의중, 판단됨, 승인대기, 막힘, 주문됨, 보유중, 팔림, 복기됨 중 하나다 |
| 근거 | 가설과 계기와 들어간 값과 손절값과 목표값과 기대값 | 하나라도 비면 주문됨으로 갈 수 없다 |
| 자료 시각 | 판단에 쓴 자료마다 알게 된 시각 | 판단 시각보다 늦을 수 없다 |
| 담당 점수 | 담당별 점수와 근거와 합의 점수 | 판단됨이 될 때 함께 남는다 |
| 계좌 종류 | 모의 또는 실전 | 실전은 실전중 템플릿에서만 나온다 |
| 승인 | 승인 번호와 승인한 내용의 지문 | 실행할 내용의 지문과 다르면 주문하지 않는다 |

- 보유 중 손절값은 좁히기만 할 수 있다.
- 손실 중인 종목에 더 사는 매매는 만들 수 없다.

출처: 기획 상세 스펙 › 상태표 › 매매

### <a id="m3"></a>M3 템플릿

| 값 | 뜻 | 규칙 |
|---|---|---|
| 상태 | 상태표의 템플릿 상태 | 모의중, 승격대기, 실전중, 멈춤 중 하나다 |
| 스타일 | 단타, 스윙, 중장기 | 하나만 고른다 |
| 조정 값 | R%와 한도와 손절 방식과 승격 기준 등 | 원칙의 절대 상한을 넘을 수 없다 |

- 실전중은 승격대기에서 내 승인으로만 된다.
- 전체 정지가 되면 실전중 템플릿은 멈춤이 된다.

출처: 기획 상세 스펙 › 상태표 › 템플릿

### <a id="m4"></a>M4 규칙 개선안

| 값 | 뜻 | 규칙 |
|---|---|---|
| 상태 | 상태표의 규칙 개선안 상태 | 제안됨, 냉각중, 반영됨, 거절됨 중 하나다 |

- 반영됨은 내 승인 뒤에만 된다.
- 반영된 규칙도 원칙의 절대 상한을 넘을 수 없다.

출처: 기획 상세 스펙 › 상태표 › 규칙 개선안

### <a id="m5"></a>M5 승인 요청

| 값 | 뜻 | 규칙 |
|---|---|---|
| 승인 번호 | 요청마다 하나 | 다시 쓰지 않는다 |

### <a id="m6"></a>M6 접속

## 오류·경계

### <a id="e1"></a>E1 접속 키 틀림

상황: 다른 기기에서 넣은 접속 키가 맞지 않는다.
보이는 것: 접속 키가 틀렸다는 안내가 보인다.
시스템 처리: 실패 횟수를 올리고 세션을 만들지 않는다.
출처: [F8](spec.md#f8) › 대안 흐름 › 1b. 접속 키가 맞는가: 아니오

### <a id="e2"></a>E2 접속 잠금

상황: 접속 키를 정한 횟수보다 많이 틀렸다.
보이는 것: 한동안 시도할 수 없다는 안내가 보인다.
시스템 처리: 그 기기의 시도를 한동안 막고 나에게 알림을 보낸다.
출처: [F8](spec.md#f8) › 예외 흐름 › 1c. 접속 키를 여러 번 틀린다

### <a id="e3"></a>E3 연결 끊김

상황: 화면과 집 컴퓨터의 연결이 끊긴다.
보이는 것: 연결이 끊겼다는 안내와 마지막으로 받은 상태가 보인다.
시스템 처리: 팀의 운용은 그대로 이어지고 다시 이어지면 놓친 이벤트부터 보낸다.
출처: [F7](spec.md#f7) › 예외 흐름 › 1b. 집 컴퓨터에 연결되지 않는다

### <a id="e4"></a>E4 키 확인 실패

상황: 넣은 키로 증권사나 AI에 닿지 않는다.
보이는 것: 키가 맞지 않다는 안내가 보인다.
시스템 처리: 그 키를 저장하지 않는다.
출처: [F6](spec.md#f6) › 예외 흐름 › 1a. 키 등록이 실패한다

### <a id="e5"></a>E5 상한 넘는 값

상황: 템플릿 값이 원칙 상한을 넘는다.
보이는 것: 그 값은 저장되지 않고 상한이 보인다.
시스템 처리: 이전 값을 그대로 둔다.
출처: [F6](spec.md#f6) › 대안 흐름 › 3a. 사용자가 원칙 상한을 넘는 값을 넣는다

### <a id="e6"></a>E6 담당 응답 실패

상황: 담당이 AI 응답을 받지 못한다.
보이는 것: 그 담당이 답하지 못했다는 표시가 보인다.
시스템 처리: 논의 중이면 팀장이 지켜보기로 정한다.
출처: [F2](spec.md#f2) › 예외 흐름 › 5a. 담당 하나가 답하지 못한다

### <a id="e7"></a>E7 승인한 내용이 바뀜

상황: 승인한 내용의 지문과 실행할 내용의 지문이 다르다.
보이는 것: 그 일이 진행되지 않았다는 안내가 보인다.
