# 가격인하 기본 원칙

확정일: 2026-11-14 (P17~P22 보안 원칙 추가: [원격 접속 보안](../research/remote-access-security.md)) · 근거: [주식 투자 철학 · 원칙 조사](../research/stock-investing-principles.md) 8장

가격인하의 규칙 엔진에 박는 원칙이에요. 템플릿, 에이전트, 복기 개선안으로 바꿀 수 없어요. 이 원칙 안에서 에이전트는 손익과 시장 상황에 따라 알아서 사고팔고, 쉬었다가 다시 시작해요.

## 바꿀 수 없는 원칙

| 번호 | 원칙 | 값 |
|---|---|---|
| P1 | 매매 1회 최대 손실: (진입가 − 손절가) × 수량 ≤ 계좌 × R% | R 절대 상한 2% |
| P2 | 손절 없는 주문 거부, 보유 중 손절은 좁히기만 허용 | 모든 스타일 |
| P3 | 일일 손실 한도에 닿으면 그날 신규 진입 정지, 청산만 허용 | 절대 상한 5% |
| P4 | 최대 낙폭에 닿으면 전체 정지(킬 스위치), 재개는 사람만 | 절대 상한 20% |
| P5 | 미수 · 신용 · 공매도 · 파생 · 레버리지 · 인버스 상품 차단 | 항상 |
| P6 | 손실 방향 추가 매수(물타기) 금지, 추가 매수는 이익 방향만 | 모든 스타일 |
| P7 | 수량 · 가격은 규칙 엔진이 계산, AI 값과 다르면 작은 쪽 | |
| P8 | 종목당 · 업종당 비중 상한 | 종목 25% · 업종 50% |
| P9 | 근거 기록(가설 · 트리거 · 진입/손절/목표 · 기대값) 없는 매매 금지 | |
| P10 | 판단 시점까지 알 수 있던 데이터만 사용, 모든 데이터에 "알게 된 시각" | |
| P11 | 시세 지연 · 데이터 이상 · API 오류 · 계좌 불일치면 신규 주문만 정지 | 손절 · 청산은 허용 |
| P12 | 주문 직전 점검: 장 시간 · 가격제한 · VI · 거래정지 · 중복 · 1회 최대 금액 · API 요청 한도 | |
| P13 | 비용 · 세금 · 슬리피지를 뺀 기대값이 양수일 때만 진입 | |
| P14 | 실전 승격: 표본 수 · 기간 · 표본 밖 성과 · 비용 반영 · 최대 낙폭 기준 통과 + 사람 승인 | |
| P15 | 규칙 변경은 승인으로만, 위험을 키우는 변경은 냉각 기간 뒤, 줄이는 변경은 즉시 | |
| P16 | AI 판단은 모델 학습 마감일 이후 구간으로만 평가 | |
| P17 | 서버는 자기 컴퓨터 안에만 열고 밖으로 나가는 길은 Tailscale 하나 | |
| P18 | 위험을 키우는 행동은 건마다 본인 재확인(인증 앱 6자리), 줄이는 행동은 바로 | |
| P19 | 승인 확인 실패와 모르는 결정은 언제나 거절 | |
| P20 | 승인 경로가 막히면 답 없음 처리를 더 보수적으로 | 신규 매수 없음, 손절 · 청산만 |
| P21 | AI 에이전트는 비밀키를 보지 못하고 AI의 말은 승인이 아니다 | |
| P22 | 비밀키와 인증 비밀값은 백업 · 화면 · 기록 어디에도 남기지 않는다 | |

## 멈춤과 재개

| 멈춤 | 재개 |
|---|---|
| 일일 손실 한도 (P3) | 다음 거래일에 에이전트가 상황을 보고 알아서 |
| 연속 손실 · 쿨다운 | 쿨다운이 끝나면 에이전트가 알아서 |
| 이상 감지 (P11) | 이상이 풀리면 에이전트가 알아서 |
| 최대 낙폭 킬 스위치 (P4) | 사람이 확인한 뒤에만 |

## 템플릿에서 조정하는 값

위 절대 상한 안에서만 바꿀 수 있어요: 1회 위험 비율 R%, 일일 손실 한도, 최대 낙폭 한도, 연속 손실 정지 횟수 · 쿨다운, 최대 동시 보유 종목 수, 종목 · 업종 비중, 최소 현금 비중, 손절 방식, 익절 방식, 최대 보유 기간, 진입 신호, 유니버스, 자동 주문 금액 한도(넘으면 승인 요청), 거래 시간대, 추격 허용 폭, 일일 최대 매매 횟수, 구독 트리거, 리밸런싱 주기.

이 문서는 시스템 설계 원칙이고 투자 조언이 아니에요.
