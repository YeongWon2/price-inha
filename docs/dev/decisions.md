## 아직 정해지지 않은 것

- 자동 업데이트를 할지(조정자 추천: 알리기만).
- 받은 설치 파일의 확인 수준(조정자 추천: 우선 체크섬만).
- 승인을 거절해 막힌 매매에 새 승인 번호를 붙일 수 있게 둘지(조정자 추천: 잠근다).
- 모의계좌의 수수료율 · 미끄러짐 · 반올림 방향 등 확인되지 않은 숫자의 실제 값.

## 2026-11-15 옛 봉투 판정을 저장소 API로 (조정자, gate 7차 6번)

- 접속 관문은 이미 읽힌 JSON 값만 받아 겹친 칸 이름을 볼 수 없다. 원래 글자를 아는 저장소에 `legacy_envelope_seqs`를 더해 판정을 한 곳에 둔다(store 7차). 관문이 저장소 파일을 직접 여는 길은 규칙(ARCH)에 어긋나 버렸다.
- secrets 5차는 지금 구현이 이미 만족해 red를 만들 수 없어, 사용자 승인으로 취소하고 4차 검토 통과 상태로 되돌렸다.

## 2026-11-15 남은 후보를 조정자가 정함 (사용자 "알아서 추천하고 개선하고 푸시해")

- ai 5차: 꺼질 때는 확인 프로세스도 끝낸다(5.6-3). 꺼지는 중이 아니면 도중에 죽이지 않는다(5.6-5)는 그대로. 작업 폴더의 자기 임시 파일을 알아보는 `is_own_work_file`을 공개한다.

- store 8차: 칸 이름 이스케이프를 푼 이름으로 판정, 훑는 범위에 위 끝.

## 2026-11-16 로드맵 T6~T22 결정 (`docs/dev/roadmap.md`)

사용자가 직접 고른 것: 1 · 2 · 11 · 12. 나머지는 사용자가 "추천대로 전부"로 승인했다. 바꾸고 싶으면 이 표를 고치고 해당 지시서를 따라 고친다.

1. **검사 스크립트의 모듈 목록 확장** (사용자 승인): `scripts/lib.sh` · `scripts/selftest.py` · `scripts/pipeline.py`의 모듈 목록과 `[crates.price-inha] internal`을 고친다. 검사 내용(무엇을 어떻게 검사하는지)은 바꾸지 않는다. 크레이트가 있는 모듈만 검사한다.
2. **조립(crates/server)을 gate에서 떼어 server 모듈로** (사용자 승인): `red/server`를 떼어 낸 시점에 붙였다. gate의 필수 번호는 `crates/gate/tests`가 확인하는 것으로 좁히고, 조립의 번호는 server.md로 옮겼다.
3. **원칙 수**: 22개(principles.md P1~P22)가 기준이다. 규칙 엔진은 P1~P13, P14~P22는 다른 모듈(template · approval · agent · backup 등)이 맡는다. spec의 "16개"는 낡은 문구다.
4. **"6자리 재확인"(A7)**: 내용 지문 앞 6자리를 카드에 보이고, 화면이 보낸 지문과 비교한다. 사용자가 숫자를 치지는 않는다.
5. **답이 없을 때**: 알림이 갔는데 답이 없으면 FN2(줄여서 다시 점검)대로, 알림 보내기에 실패했으면 P20대로 사지 않는다.
6. **다시 켠 뒤 기다리던 승인**: 신호의 유효 시간 안이면 유지, 지났으면 만료. 백업에서 되살리면 전부 만료(M5).
7. **승인 뒤 시세가 바뀔 때**: 승인이 필요한 주문은 지정가로만 내고 가격을 지문에 넣는다. 시세가 바뀌어도 다시 묻지 않는다.
8. **접속 키**: 프로그램이 약 100비트 키를 만들어 한 번만 보여 준다. 소금을 친 SHA-256으로 둔다. 스펙의 "내가 정한"은 "내가 설정한"으로 읽는다.
9. **잠금**: 스펙 N3(5번 · 15분). 메모리에만 두고, 들어온 세션은 유지, 그 컴퓨터에서 풀 수 있다.
10. **원격 세션 쿠키**: Max-Age 30일, SameSite=Strict, 키를 바꾸면 끊긴다.
11. **임베딩** (사용자 결정): 키워드 · 조건 검색을 먼저 만들고, 뜻 검색은 포트만 두고 "쓸 수 없음"으로 돌려준다. 공급자는 사용자가 고른 뒤 붙인다. `dev.md` D10을 이렇게 고쳤다.
12. **AI 도구 호출** (사용자 결정): 답 글 안의 정해진 JSON 행동 형식. API 키 · CLI 백엔드가 같은 길로 간다. 원본(Hermes)의 네이티브 도구 호출과 "의도해서 다름".
13. **채팅 스트리밍**: 1차는 queued → thinking → complete. 스트리밍은 2차.
14. **논의 순서**: 0라운드는 지명, 그 뒤는 멘션(Hermes). 상한 3라운드 · 10글 · 6명, 닿으면 지켜보기.
15. **점수와 판단**: 논의 → 담당별 점수 턴(JSON) → 팀장 판단 턴. 담당 하나가 실패하면 합의 불가로 지켜보기.
16. **턴 시간 제한**: 장중 담당 턴 무응답 60초 · 전체 180초, 채팅 180 · 600초, 반복 상한 20.
