# gate 모듈 (T5)

크레이트 `pi-gate`(폴더 `crates/gate/`)와 실행 파일 `price-inha`(폴더 `crates/server/`).
구성 요소 A2 접속 관문과 실시간 연결, 그리고 조립. `pi-gate`는 `pi-store`만 쓸 수 있고, `price-inha`는 모든 모듈을 쓸 수 있다.
근거: `dev.md`의 D2 · D11 · C2 · C15 · E3 · M6, `spec.md`의 F8 기본 흐름과 F7 1 · 1b.

store · secrets · ai · market 모듈이 끝난 뒤에 한다. 그 모듈들의 공개 API를 읽고 그대로 쓴다(고치지 않는다).

## 원본 동작 근거

- 대조표: `docs/dev/conformance.md` 4장 "접속 관문 · 실시간 연결 · 설정".
- 따르는 원본: DeskRPG의 실시간 이벤트 — `docs/research/deskrpg.md` 3-2. Hermes api_server와 스트리밍 전달 계약 — `docs/research/hermes-agent.md` 5.2 · 5.3. 플러그인 이벤트 스트림과 다시 잇기 — `docs/research/deskrpg-hermes-plugin.md` 3-4 · 5장. 로컬 접속 — `docs/research/remote-access-security.md`.
- 의도해서 다른 것: Socket.IO · SSE 대신 WebSocket 하나 + REST(D11), 그 컴퓨터에서만 열고 접속 키는 나중(D2), 처음 설정은 브라우저 화면(사용자 결정).
- 모르고 달랐던 것(다음 차례에 고친다): 연결 keepalive, 이벤트 종류 이름 규칙, 보안 응답 헤더, 저장되는(번호 있는) 이벤트를 내는 곳.

## pi-gate가 만드는 것

1. **그 컴퓨터에서만 열기 (D2)**: 기본 주소는 `127.0.0.1`이다. 다른 주소로 열려면 설정을 분명히 줘야 한다.
2. **그 컴퓨터인지 확인 (C15)**: 연결의 **실제 상대 주소**가 루프백이면 접속 키 없이 세션을 만든다. `X-Forwarded-For` 같은 헤더는 믿지 않는다. 루프백이 아닌 요청은 이번 작업에서는 모두 거부한다(401, 접속 키는 T17).
3. **Host · Origin 확인**: `Host` 헤더가 허용 목록(기본 `localhost`, `127.0.0.1`, `[::1]`과 포트)에 없으면 거부한다(DNS rebinding 방지). 상태를 바꾸는 요청과 웹소켓 연결은 `Origin`이 같은 출처가 아니면 거부한다.
4. **세션**: 추측할 수 없는 무작위 값(256비트). 쿠키는 `HttpOnly` · `SameSite=Strict` · `Path=/`. 서버에는 해시만 둔다. 세션 없이 보호된 경로를 부르면 401.
5. **접속 기록 (M6 · F8 3)**: 들어올 때마다 언제 · 어디서(상대 주소) · 무엇을(들어옴)을 `pi-store`의 접속 기록에 남긴다.
6. **실시간 연결 (C2 · D11 · E3)**: 웹소켓 경로 하나. 세션이 있어야 한다. 연결할 때 "마지막으로 받은 이벤트 번호"를 주면 그 뒤의 이벤트를 `pi-store`에서 읽어 순서대로 보내고, 이어서 새 이벤트를 보낸다. 번호가 빠지거나 겹치지 않는다. 끊겼다가 다시 이어도 같다.
   - 이벤트 프레임은 JSON이고 번호 · 종류 · 내용 · 시각을 가진다.
   - 시세처럼 자주 바뀌는 것은 저장하지 않는 "지나가는 이벤트"로 따로 보낸다(번호 없음). 연결하면 가장 최근 시세 묶음을 먼저 보낸다.
   - 느린 연결이 서버를 막지 않는다(밀리면 그 연결만 끊고, 다시 이으면 번호로 이어 받는다).
7. **이벤트 내보내기**: 다른 모듈이 `발행(종류, 내용)`을 부르면 저장하고 연결된 화면에 보낸다.
8. **가리기 자리**: 화면으로 나가는 글에 가리기 함수를 끼울 수 있는 자리(trait 또는 함수 인자)를 둔다. `pi-gate`는 `pi-secrets`를 직접 쓰지 않는다.

## price-inha(실행 파일)가 만드는 것

1. 설정(보관 폴더, 여는 주소와 포트, 지켜볼 종목, 시세 간격)을 환경 변수나 인자로 받는다. 비밀 값은 인자로 받지 않는다.
2. `pi-ai` · `pi-market`의 `CredentialSource`를 `pi-secrets`로 구현하고, 두 모듈의 `verify`를 `pi-secrets`의 확인기 trait에 잇는다(조립).
3. 저장소를 열고, 증권사 키가 등록돼 있으면 토스 어댑터로 시세를 지켜보고, **없으면 시세를 받지 않고 "증권사 키가 없음" 상태를 화면에 알린다(V31)**. `--demo`를 주면 가짜 어댑터로 시세를 흘린다(화면에 시연용이라고 표시).
4. 시세가 30초 넘게 늦으면 "시세 늦음" 지나가는 이벤트를 보낸다(N6).
5. 작은 화면 한 장(`web/index.html`, 서버가 내준다): 실시간 연결로 시세가 바뀌는 것이 보인다. 끊기면 "연결 끊김"과 마지막 상태가 보이고 다시 이어진다(E3). 3D 사무실은 나중 작업이다. 화면은 바깥 주소에서 아무것도 불러오지 않는다.
6. 끌 때(Ctrl+C) 연결을 정리하고 저장소를 닫는다. 다시 켜면 이벤트 번호가 이어진다(V6).

## 2차 작업 (1차 AI 검토 되돌림)

1차는 구현이 끝났다. 2차는 아래를 **테스트로 먼저 쓰고** 구현한다. 접속 관문(`pi-gate`)의 접속 확인은 1차 검토에서 건너뛰는 길이 없었으니 그 동작은 바꾸지 않는다. 공개 API 모양은 더하기만 한다.

### price-inha (조립)

1. **증권사가 받지 않는 키로 계속 두드리지 않는다**: 토큰 발급이나 시세 받기가 인증 실패 · 허용 IP 아님으로 실패하면 다시 시도하는 간격을 늘린다(물러서기, 상한 있음 — 값은 설정). 연결 실패 · 장애도 같다. 성공하면 원래 간격으로 돌아온다.
2. **시세 상태를 사실대로 알린다**: "증권사 시세(live)"는 시세를 실제로 한 번 받은 뒤에만 알린다. 그 전에는 "연결 중", 실패하면 "증권사가 키를 받지 않음" / "증권사에 닿지 않음"을 구분해 알린다. 화면도 그 글자를 보여 준다.
3. **같은 경고를 끝없이 찍지 않는다**: 같은 실패가 되풀이될 때 기록은 상태가 바뀔 때와 정한 간격마다만 남긴다(키 파일이 깨졌을 때의 경고도 같다).
4. **장 시간을 모르면 "모름"이다 (N6)**: 달력을 한 번도 못 받았거나 가진 달력이 지금 시각을 덮지 않으면 "장 닫힘"으로 보지 않는다. 시세가 30초 넘게 오지 않으면 "시세 늦음"을 알리거나, 최소한 "장 시간을 몰라 늦음 판단을 못 함"을 따로 알린다(조용히 넘어가지 않는다). 달력을 아는 동안 장이 닫힌 것은 지금처럼 조용하다.
5. **안내 주소**: 모든 주소로 열었을 때(`0.0.0.0` · `::`) 띄울 때 알려 주는 주소는 실제로 열리는 주소(루프백)다.

### pi-gate

6. **가린 뒤에도 프레임은 JSON이다**: 등록된 값이 숫자뿐이라 JSON 숫자와 겹쳐도, 가린 결과가 깨진 JSON이 되지 않는다(가려진 글자는 언제나 문자열 자리에 들어간다).
7. **저장하기 전에도 가린다 (N8)**: 발행된 이벤트의 내용은 저장소에 쓰기 전에 가린다. 저장된 것을 다시 보낼 때도 지금의 가리기를 한 번 더 거친다.
8. **나가는 프레임 크기에 끝이 있다**: 정한 크기(설정값)를 넘는 내용은 발행을 거부한다(오류로 알린다).

## 3차 작업: 시작 전 필수 설정 + 2차 검토 되돌림 (2026-11-14 사용자 결정)

**필수 설정이 모두 등록되기 전에는 시작하지 않는다.** 처음 열면 설정 화면으로 가고, 필수 항목이 다 등록되면 그때 시작한다.
근거: `dev.md`의 C3 · C16 · E4 · V31 · V46, `spec.md`의 F6 기본 흐름 1.

### 필수 항목

| 항목 | 필수인가 | 등록됐다고 보는 때 |
|---|---|---|
| 증권사 키 (`client_id` · `client_secret`) | 필수 | 증권사에 실제로 닿는 것이 확인되어 저장됐을 때 |
| AI 키 (API 키 또는 구독 OAuth 토큰 가운데 하나) | 필수 | AI 공급자에 실제로 닿는 것이 확인되어 저장됐을 때 |
| 지켜볼 종목 | 필수 | 하나 이상 저장됐을 때 (인자 · 환경 변수로 줬으면 그것으로 채워진다) |
| 자료 키 | 선택 | 확인할 곳이 생길 때까지 필수가 아니다 |

필수 항목의 목록은 한 곳(코드의 표 하나)에 두어, 나중에 템플릿 고르기(T8) 같은 항목을 더하기 쉽게 한다.

### 규칙

1. **시작 조건**: 필수 항목이 하나라도 빠져 있으면 시세 받기와 그 뒤의 일을 시작하지 않는다. 바깥으로 나가는 요청은 키 확인뿐이다(V31).
2. **설정 상태**: 세션이 있어야 읽을 수 있다. 항목마다 "등록됨 / 안 됨"과 필수 여부, 그리고 "모두 갖춰졌는가"만 알려 준다. 키의 값 · 일부 · 길이는 알려 주지 않는다(V46).
3. **키 등록 (C3 · C16)**: 세션과 같은 출처(Origin)가 있어야 한다. 받은 키는 `pi-secrets`의 `register`로 넘겨 실제로 닿는지 확인하고, 닿지 않으면 저장하지 않고 이유(키가 맞지 않음 / 서버에 닿지 않음)만 알린다(E4). 성공하면 "등록됨"만 돌려준다. 응답 · 오류 · 기록 · 이벤트 어디에도 받은 값이 나오지 않는다.
4. **키 등록은 그 컴퓨터에서만**: 루프백이 아닌 요청은 접속 키(T17)가 생긴 뒤에도 키를 등록하거나 바꿀 수 없다.
5. **다 등록되면 바로 시작한다**: 마지막 필수 항목이 등록되면 다시 켜지 않아도 시작하고, 화면은 설정 화면에서 본 화면으로 넘어간다. 그 사실은 실시간 연결로도 알려진다.
6. **이미 시작한 뒤 키를 다시 등록하면**(C16) 새 키로 이어 간다. 필수 항목이 빠지면(키 파일이 지워짐 등) 멈추고 설정 화면으로 돌아간다.
7. **화면**: 필수 항목이 빠져 있으면 화면은 설정 화면만 보여 준다. 항목마다 입력 칸과 등록 단추, 등록 여부를 보여 준다. 키 입력 칸은 가려진 칸이고, 등록한 뒤 칸을 비운다. 값을 브라우저 저장소나 주소에 남기지 않는다.
8. **시연 모드**: `--demo`는 설정 없이 바로 시작한다(가짜 시세). 화면에 시연이라고 표시한다.
9. **잘못된 입력과 되풀이**: 빈 값 · 너무 짧은 값 · 모르는 항목은 확인기를 부르기 전에 거부한다. 키 등록 시도에는 횟수 제한이 있다(증권사 · AI 서버를 계속 두드리지 않게).

### 2차 AI 검토 되돌림에서 함께 고치는 것 (시세 흐름)

10. **지켜볼 종목이 없으면 증권사를 부르지 않는다**: 종목이 비어 있으면 시세도 달력도 토큰도 요청하지 않는다(필수 항목이 빠진 것이므로 시작 전 상태다).
11. **달력 받기 실패도 물러서기와 시세 상태를 탄다**: 달력을 받다가 인증 실패 · 허용 IP 아님이면 "증권사가 키를 받지 않음"으로 알리고 간격을 늘린다. 달력만 따로 고정 간격으로 두드리지 않는다. 달력 다시 받는 간격은 설정값이다.
12. **빈 시세는 성공이 아니다**: 증권사가 요청한 종목의 시세를 하나도 주지 않으면 "연결 중"에 머물며 원래 간격으로 계속 두드리지 않는다(물러선다).
13. **증권사가 요청을 거절한 것은 "닿지 않음"이 아니다**: 4xx 거절(종목 없음 등)은 "증권사가 요청을 거절함 (종목을 확인)"으로 따로 알린다. 종목 하나가 틀려도 나머지 종목의 시세는 나온다(틀린 종목은 빼고 받거나 하나씩 나눠 받는다). 어느 종목이 거절됐는지 화면에 보인다.
14. **등록이 흐름을 깨운다**: 키나 종목이 새로 등록되면 물러서 있는 중이어도 바로 다시 시도한다(최대 간격을 기다리지 않는다).
15. **한도 초과의 기다림을 따른다**: 증권사가 준 기다림(`Retry-After`)이 있으면 다음 시도는 그보다 빠르지 않다. 기다리는 동안에도 "시세 늦음" 판단은 제때 돈다(요청이 끝나길 기다리느라 늦어지지 않는다).
16. **한 번도 안 온 종목**: 요청했는데 시세가 한 번도 오지 않은 종목은 30초 뒤 "시세 늦음" 목록에 든다(조용히 빠지지 않는다).

## 4차 작업 (3차 AI 검토의 참고 — 아직 시작하지 않음)

3차는 검토를 통과했다(키 등록 길의 접속 확인 · 값 새는 길 · 확인 없이 저장되는 길에서 건너뛰는 길 없음).

1. **시작한 뒤에도 화면에서 설정을 고칠 수 있다**: 본 화면에서 설정 화면을 다시 열어 종목과 키를 다시 등록할 수 있다. "거절한 종목" · "증권사가 키를 받지 않음" 옆에 고치러 가는 길이 있다.
2. **거절을 봤고 시세가 0건이면 바로 "증권사가 요청을 거절함"이다**: 종목이 많고 전부 거절될 때 가려내는 동안 "연결 중"으로 보이지 않는다.
3. **종목 등록도 아껴 깨운다**: 목록이 바뀌었을 때만 흐름을 깨운다. 종목 등록에도 횟수 제한을 둔다.
4. **이미 있는 키를 덮어쓸 때는 확인을 한 번 더 거친다**(T17과 함께): 같은 컴퓨터의 다른 프로세스가 키를 바꿔 끼우지 못하게. 자료 키 시도가 다른 키 등록을 막지 않게 횟수를 따로 센다.
5. **키 입력 칸**: 브라우저가 저장을 권하지 않게 `autocomplete="new-password"`. 자료 키는 "아직 등록할 수 없음"으로 안내한다.
6. **받은 키 값은 다 쓰면 바로 지운다**: 요청 본문과 중간 값을 0으로 덮는다.
8. **저장되는 이벤트는 시각과 함께, 저장된 이름으로 보낸다** (store 3차 검토): `append`(시각 없음) 대신 `append_at`을 쓰고 시각 봉투를 없앤다. 화면에 보내는 프레임은 저장소가 저장한 이름(앞뒤 공백을 뗀 것)으로 만든다(Hermes는 저장된 줄을 돌려받아 그 줄로 보낸다).
7. **`Retry-After`는 다시 시작해도 기억한다**. 종목 글자에서 `..`를 받지 않는다.

## 하지 않는 것

접속 키 · 잠금 · 키 바꾸기(T17), 승인 · 채팅 · 알림, 웹 푸시, TLS.

## 테스트 주의

서버를 `127.0.0.1:0`(빈 포트)에 띄워 실제 HTTP · 웹소켓으로 확인한다. 루프백이 아닌 상대는 상대 주소를 넣어 주는 테스트용 자리로 흉내 낸다. 실행 파일 테스트는 임시 보관 폴더와 `--demo`로 띄워 시세가 실시간 연결로 오는 것까지 본다.
