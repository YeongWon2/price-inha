# channel 모듈 작업 지시서 (pi-channel, `crates/channel`)

메신저 채널: 텔레그램 · 슬랙으로 글을 주고받는 한 겹. 결정 24(사용자 "텔레그램, 슬랙 등등 메신저도 등록 가능하게… 메신저를 연결해서 게이트를 둘 수도").
조사: `docs/research/onboarding-messenger.md` 2.4 · 2.5 · 2.6 · 5장 (다). 원본(OpenClaw · Hermes)과 같은 동작으로 만든다(코드는 옮기지 않는다).

## 이 모듈이 하는 일과 하지 않는 일

- 한다: 채널 추상화(`Channel`), 텔레그램 어댑터(1차), 슬랙 어댑터(2차), 보낸 사람 판정(페어링 · 허용 목록), 나가는 글 자르기 · 가림 확인, 들어온 글을 명령으로 읽기.
- 하지 않는다: 무엇을 언제 보낼지 정하기(server · notify가 정한다), 승인 처리(approval이 한다 — 이 모듈은 "누가 어떤 단추를 눌렀다"만 알린다), 저장(포트로 받는다 — 저장소 판을 올리지 않는다), 환경 변수 읽기(토큰 · 주소는 생성자 인자로).
- 바깥 주소(텔레그램 API · 슬랙 API)는 설정 값으로 받는다. 시험은 그 자리에 로컬 가짜 서버를 둔다(AGENTS 5번). 밖에서 들어오는 포트를 열지 않는다(long polling · Socket Mode).

## 1차 작업 (2026-11-26 조정자, 결정 24 — 텔레그램 · 페어링)

근거: `docs/research/onboarding-messenger.md` 2.4(텔레그램 · 페어링 · DM 정책) · 2.5(글 길이 · 가림) · 5장 (다).

1. **채널 한 겹**: `trait Channel` — `name()`, `check() → 봇 이름`(토큰이 맞는지 확인), `poll(cursor) → (받은 것들, 다음 cursor)`, `send(to, 글) → 보낸 글 번호들`, `limits() → {text_max}`. 받은 것은 `Inbound { channel, sender(숫자 ID 글자), chat, is_direct, text, at, message_id }`.
2. **텔레그램 어댑터**: `getMe`로 확인, `getUpdates` long polling(offset = 마지막 update_id + 1, 타임아웃은 설정 값), `sendMessage`. 토큰은 주소 경로에 들어가므로 **오류 · 기록 어디에도 주소를 통째로 찍지 않는다**(토큰 자리를 가린 글만). HTTP 오류 · 429(`retry_after`)는 종류 있는 오류로 돌려주고, 부르는 쪽이 정한 간격으로 다시 한다(이 모듈은 스스로 무한히 다시 하지 않는다). 글이 `text_max`(텔레그램 4000자 — 원본 값)를 넘으면 줄 경계에서 나눠 차례로 보낸다(나눈 조각마다 한도 안, 글자 수는 유니코드 글자 기준).
3. **보낸 사람 판정**(원본과 같게): `Gatekeeper::judge(inbound, now) → Allowed | PairingIssued{code} | PairingPending | Ignored{까닭}`.
   - 허용 목록(승인된 숫자 ID)에 있으면 `Allowed`.
   - 없고 1:1 대화면 페어링 요청을 만든다: 코드 8자리, 글자표 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`(헷갈리는 0 · O · 1 · I 없음), 1시간 뒤 만료, 기다리는 요청은 많아야 3건(넘으면 새로 만들지 않고 `Ignored`), 같은 보낸 사람은 10분에 한 번만 새 코드. 코드는 요청이 **새로 생겼을 때만** 답으로 준다(같은 사람이 또 말하면 `PairingPending` — 코드를 다시 찍지 않는다).
   - 그룹 · 채널 글은 `Ignored`(허용된 사람이어도 1:1이 아니면 받지 않는다 — 결정 24 "DM만").
   - **승인은 이 모듈 밖에서**: `approve(code, now)`는 서버(같은 컴퓨터의 터미널 · 화면)가 부른다. 맞는 코드면 그 보낸 사람을 허용 목록에 넣고 요청을 지운다. 틀린 코드 5번이면 1시간 동안 승인을 받지 않는다(원본 Hermes). 허용 목록은 많아야 1명(결정 24 — 이미 있으면 `approve`가 거절하고 "먼저 지금 사람을 빼라"를 말한다). `revoke(sender)`로 뺀다.
   - 코드는 예측할 수 없게 만든다(암호용 난수). 코드 · 토큰은 기록에 찍지 않는다.
   - 상태(허용 목록 · 기다리는 요청 · 실패 횟수)는 `PairingBook` 포트(읽기 · 쓰기)로 받는다. 시계도 넣어 준다.
4. **나가는 글의 가림**: `send`는 가린 글만 받는다 — 타입으로 강제한다(`Redacted` 글만 받는 생성자: 부르는 쪽이 가리개를 거쳐야 만들 수 있다). 가리기에 실패한 글은 만들 수 없으므로 보내지지 않는다(결정 24 "가리기에 실패하면 보내지 않는다").
5. **명령 읽기**: 허용된 사람의 글을 `Command`로 읽는다 — `/status`(상태) · `/stop`(멈춤) · `/help` · `/approvals`(기다리는 승인 목록) · `/reject <짧은 번호>`(거절) · 그 밖은 `Unknown(글)`. 대소문자 · 앞뒤 공백 · 텔레그램의 `/cmd@봇이름` 꼴을 받는다. **승인(`/approve`)은 명령에 없다**(결정 24 — 읽어도 `Unknown`이 아니라 "승인은 웹에서만"을 뜻하는 `ApproveNotHere`로 돌려 부르는 쪽이 안내하게). 이 모듈은 읽기만 하고 실행하지 않는다.

- 원본 동작 근거: `docs/research/onboarding-messenger.md` 2.4(페어링 8자리 · 글자표 · 1시간 · 대기 3건 · 새 요청 때만 코드 답 · 틀린 승인 5회 잠금 · 그룹 무시 · long polling) · 2.5(텔레그램 4000자 나누기). 허용 1명 · 승인 명령 없음 · 가린 글만 보내기는 결정 24(우리 것).
- 시험으로 확인할 것(로컬 가짜 텔레그램 서버 · 넣어 준 시계): `check`가 봇 이름을 주고 틀린 토큰이면 종류 있는 오류(오류 글에 토큰 없음) / `poll`이 offset을 잇고 빈 응답 · 깨진 응답 · 429(`retry_after`)를 가려 돌려줌 / 긴 글을 줄 경계에서 나눠 차례로 보냄(조각마다 한도 안, 한글 · 이모지 글자 수) / 판정: 허용된 사람 `Allowed` · 처음 보는 1:1은 코드 발급(8자리 · 글자표 안) · 같은 사람 다시 말하면 `PairingPending` · 10분 안 재발급 없음 · 1시간 뒤 만료 · 대기 3건 넘으면 `Ignored` · 그룹 글 `Ignored` / `approve`: 맞는 코드로 허용 · 요청 지움 · 틀린 코드 5번 뒤 1시간 잠금 · 이미 1명 있으면 거절 / `revoke` 뒤 다시 처음 보는 사람 / 코드가 매번 다름(같은 시계 · 같은 보낸 사람이어도) / 가리지 않은 글로는 보낼 글을 만들 수 없음(가리개가 실패하면 오류) / 명령 읽기 표(각 명령 · `@봇이름` 꼴 · `/approve`는 `ApproveNotHere`) / 기록(tracing)에 토큰 · 코드가 없음 / 가짜 서버 밖 요청 0건.
