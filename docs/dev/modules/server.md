# server 모듈 (조립 · 실행 파일)

실행 파일 `price-inha`, 폴더 `crates/server/`. 모든 모듈을 쓸 수 있는 유일한 곳이고, 실행 파일은 이것 하나다.
2026-11-16에 gate 모듈에서 떼어 냈다(사용자 승인, `docs/dev/decisions.md` 2026-11-16 2번). 1~8차의 조립 작업 기록은 `docs/dev/modules/gate.md`의 "price-inha(실행 파일)가 만드는 것"과 2~8차 절에 있다. 잠긴 테스트(`crates/server/tests/`)는 그때 것을 그대로 이어받고, `red/server` 태그로 잠근다.

## 트리거를 조립할 때 (trigger 3차 검토의 참고)

- `Trigger::settle()`을 `select!` 같은 취소될 수 있는 자리에 두지 않는다. 끝난 결과는 `drain_finished()`로 가져가고, 가져갈 때 tick을 한 번 깨워 실행이 끝난 작업의 기한 회차가 늦지 않게 한다.

## 사무실 화면을 조립할 때 (office 1차 · gate 9차 검토의 참고)

- 경로: `GET /api/office` → `{agents, pending, last_seq}`(마지막 번호를 **먼저** 읽고 `agents()` · `pending_responses()`를 읽는다), `POST /api/office/chat` 몸통 `{room, agent, text, sourceMessageId}`. 글 길이 상한 500자, 같은 기기 2초 간격, `sourceMessageId` 길이 상한(원본 값).
- 채팅 응답 타임아웃(무응답 180초 · 전체 600초)과 취소를 에이전트 조립에서 건다.
- 팀 방의 사용자 글도 이벤트로 낸다(다른 화면 · 새로 고침에서 질문이 보이게).
- 다른 기기에서 키를 넣는 화면: 원격은 세션 없이 401이므로 키 입력만 하는 작은 공개 쪽을 따로 둔다.

### 1차 보강 (1차 검토 되돌림)

- 그날 시작 평가액과 계좌 최고 평가액을 저장소에 남기고 열 때 되읽는다. 다시 켜도 하루 손실 한도(P3) · 최대 낙폭 전체 정지(P4)의 기준이 바뀌지 않는다. 최고 평가액은 처음 돈 아래로 내려가지 않는다. 시험: 손실을 낸 뒤 앱을 다시 띄워 남은 한도만큼만 더 잃으면 멈춘다.
- 기록 가리기는 App과 같은 비밀 보관소(`Arc`)를 쓴다. 실행 중에 등록한 키도 표준 오류 · 기록에서 가려진다(E38 · N8). 시험: 띄운 뒤 키를 등록하고 그 값을 tracing으로 찍으면 가려진다.
- 승인 길(`run_approved`)도 쉬는 날(E19) 검사를 한다: 쉬는 날로 정한 뒤에 승인된 사는 주문 · 익절은 내지 않는다.
- 참고(되돌림 아님, 2차 이후): 다시 켠 뒤 기다리던 승인은 막힘으로 정리하고 답은 `content_changed` 대신 막힘 사유로; 점검과 제출 사이 팀 상태 변화(`team_turn`); 쉬기 결정 사유를 "장 마감" 대신 맞는 사유로.
- 1차 보강 검토 참고: `take_payload`가 저장 전에 '남긴 것'으로 표시해 `append_at` 실패 때 다음 변화까지 다시 남기지 않는다(저장 성공 뒤 표시로). `TradingWiring::default`와 `default_wiring` 중복.

### 2차 보강 (2차 검토 되돌림)

- 개선안 승인은 승인 때의 지금 규칙(current)과 개선안의 after로 `pi_journal::increases_risk`를 **다시** 판정하고, 위험하면 냉각으로 보낸다(journal `approve` · `approve_as_risky`와 같은 길, 가능하면 journal의 `approve`를 그대로 부른다). 시험: 같은 규칙에서 낸 개선안 둘 중 한도를 좁히는 것을 먼저 반영한 뒤 다른 것을 승인하면 냉각중이 되고 한도가 넓어지지 않는다.
- 담당 모델 기본값은 지금 모델 `claude-sonnet-5-5`로 바꾼다(조정자 결정, 사용자가 고르는 설정은 다음 차수 후보).
- 참고(되돌림 아님): 거절 경로가 승인 모듈 거절 답의 오류를 버림(`let _`); `proposal_notices`가 이벤트를 매번 처음부터 읽음; 종목 → DART 고유번호 표가 비어 실행 파일은 공시 논의를 안 함; V32 거래량 · V35 뉴스 미덮음; 트리거 단조 시계가 실제 `Instant`.
- 2차 보강 검토 참고: `trading.params()`가 없음 · 오류이면 승인을 쓰지 않은 채 "rejected/not_found"로 답한다(승인은 남음).

### 후보 일괄 처리 때 다른 모듈에서 넘어온 것 (5차)
- 손절 감시 조립: 시세마다 `exec.stop_hits` → `stop_draft` → `rules::check` → `issue` → `sell(StopLoss)`. 이상 감지 뒤 팀 상태 바꾸기.
- 되살리기를 `pi_backup::restore_in`으로 옮겨 임시 폴더를 넘긴다.
- journal · agent가 가린 글만 knowledge에 넘기는지 확인(M7). 자동 회상은 `recall_by_condition`.
- 손절 주문 안은 시장가 · 상품 모름(exec 3차 결정). agent가 AI 손절값을 통화 최소 단위(미국 센트)로 넣는지 확인.
- `Notifier::release_held()`를 조용한 시간이 끝날 때와 구독이 생길 때 부른다.
- 폰 화면이 가정한 경로(/api/push/key, /api/push/subscribe, /api/notices, /api/approvals/{id}/approve|reject, /api/daily-summary)를 서버 경로와 맞춘다.
- 사무실 스냅샷은 `last_seq`를 먼저 읽고 `agents()` · `pending_responses()`를 읽는다.
- notify 시험용 `redirect_to`를 시험 전용 feature로 묶는다(server Cargo.toml · 시험).
- 점검 표시: `trading/order.rs`의 `pi_rules::issue`를 `issue_for_trade(&authority, passed, trade.0)`으로 바꾸고, 사는 수량을 `set_trade_quantity`로 저장한다. 그 뒤 exec가 묶이지 않은 표시(`None`)도 막도록 exec 잠긴 시험 도우미(`common.rs` permit)를 묶인 표시로 바로잡는다.
- store 방 로그 마지막 번호 조회 API가 생기면 agent가 쓴다(지금은 500줄씩 읽음).

## 5차 작업 (후보 일괄 처리)

테스트: `crates/server/tests/round12/`. "4차 후보"와 "다른 모듈에서 넘어온 것(5차)"을 처리했다(store 방 로그 마지막 번호 API는 다음 다듬기).

- 점검 표시는 `pi_rules::issue_for_trade(&authority, passed, trade.0)`로 매매에 묶고, 사는 주문은 규칙 엔진이 정한 수량을 `set_trade_quantity`로 남긴다(승인이 붙어 잠겼으면 그대로 둔다).
- 주문 안 도구(`submit_order_draft`)는 매매 담당이 적은 `ai_quantity`를 넘기고, `ai_price`는 진입가와 견줘 작은 쪽을 지정가로 쓴다(P7). 저장소 금액은 통화 최소 단위로 읽는다(미국 센트 ÷ 100).
- 손절 감시: 시세마다 `stop_hits` → `stop_draft` → 주문 길(규칙 점검 → 묶인 표시 → `sell(StopLoss)`). 쉬는 날 검사는 건너뛰고, 이상 감지 멈춤은 주문 길이 팀 상태로 옮긴다. 같은 매매에 손절 주문이 걸려 있으면 다시 내지 않고 그 주문을 돌려준다(E30). 기준가는 그 시세를 쓴다.
- 지식 검색을 담당 도구 `knowledge_search`로 등록했다(모든 담당). 자동 회상은 같은 종목을 `recall_by_condition`으로 먼저 찾고 모자라면 키워드 자동 회상으로 채운다(둘 다 바깥 자료 조각은 넘기지 않음, M7). 복기 색인은 가린 글만 넘김을 확인했다.
- 공식 조립의 종목 → DART 고유번호 표(`known_corp_codes`, 확인한 2종목).
- 백업 설정 화면 `GET/POST /api/setup/backup`(저장소 `소유자/이름` · age 공개키, 보관 폴더 `backup-settings.json`, 다시 켜도 남고 `reach.backup`의 저장소 · 공개키보다 앞선다). 되살리기 `restore_backup`은 `pi_backup::restore_in`에 대상 옆 작업 폴더를 넘기고 끝나면 지운다.
- 구독이 생길 때와 앱 시계로 1분마다 `release_held()`를 부른다(조용한 시간이면 아무것도 안 한다). 사무실 채팅 간격 표는 간격이 지난 기기를 지운다.
- 확인만 한 것: 폰 화면 경로 6개는 서버 경로와 같다. 사무실 스냅샷은 이미 `last_seq`를 먼저 읽는다.
- 하루 시험(V47)에 기록 출력과 백업 묶음을 넣었다.
- 다른 기기의 키 입력: 공개 경로 없이 세션(TOTP 로그인) 뒤에 둔다. 화면 `GET /keys`(`web/keys.html`), 등록 `POST /api/remote/keys`(몸통 · 상한 · 답은 `/api/setup/keys`와 같고 답은 등록 여부뿐). 키 값은 저장만 하고 다시 보여 주지 않는다. 시험은 `page.rs` 단위 시험(잠긴 뒤라 HTTP 경로 시험은 다음 차수).

## 6차 작업 (마지막 차수 검토 참고)
- `/keys` · `POST /api/remote/keys` HTTP 경로 시험: 세션 없이 401, 다른 출처 POST 거부, 세션이면 등록되고 답에 값이 없다.
- `POST /api/setup/backup`은 `/api/setup/keys`처럼 그 컴퓨터에서만 받는다(원격에서 공개키를 바꾸지 못한다).
- 되살리기 중 꺼져 남은 작업 폴더는 다음 되살리기 · 켤 때 지운다.
- notify 시험용 `redirect_to`를 시험 전용 feature로 묶는다(notify Cargo.toml에 feature, server는 dev-dependency에서만 켠다). notify 쪽 고침은 같은 차수에 notify 차수로 연다.

### 6차 구현 메모
테스트: `crates/server/tests/round13/`. 위 네 항목을 모두 처리했다.

- `/keys` · `POST /api/remote/keys` HTTP 경로 시험: 세션 없이 401(확인기를 부르지 않음), 다른 출처 POST는 4xx, 세션이면 `{"registered": true}`만 돌려주고 키 값이 없다.
- `POST /api/setup/backup`은 `/api/setup/keys`와 같은 장치(`pi_gate::local_only`)로 그 컴퓨터에서만 받는다. 원격 세션은 `GET`은 되고 `POST`는 403(`LOCAL_ONLY_STATUS`). 같은 경로를 `GET` 라우터와 `local_only`로 감싼 `POST` 라우터로 나눠 합친다.
- 되살리기 작업 폴더(`<보관 폴더>.restore-work`)는 되살리기 앞뒤로 지우고, 켤 때(`App::assemble` 처음)도 지운다.
- notify의 `redirect_to`는 `test-redirect` feature 뒤에 있고, server는 dev-dependency에서만 켠다(일반 의존성은 그대로).
- 시험의 원격 세션은 저장소에 접속 키 해시를 직접 두고 그 키로 들어간다(dev-dependency `sha2`). 서버에는 아직 접속 키를 만드는 길이 없다(다음 차수 후보: 접속 키 발급 화면 · 명령).

## 7차 작업 (6차에서 드러난 빈틈: 접속 키 조립)
gate 9차(T17)가 만든 `GateServer::access_keys()`(`AccessKeys`)를 조립한다. 이미 이어진 것은 확인만 하고 빠진 것만 한다.
- 접속 키 발급: 그 컴퓨터에서만(`pi_gate::local_only`) `POST`로 새 키를 만들고 답에 **한 번만** 보여 준다(기록 · 다른 응답에 다시 나오지 않는다). 설정 화면에 "접속 키 만들기/바꾸기" 칸. 바꾸면 앞 세대 원격 세션이 끊긴다(V41).
- 잠금 풀기: 그 컴퓨터에서만 막힌 기기를 푼다(N3).
- 잠금 알림: gate 잠금 알림 포트를 notify로 잇는다(E2, 조용한 시간을 무시하는 종류).
- 접속 기록 보기: 그 컴퓨터 · 세션에서 기기 · 시각을 본다(V40).
- 시험: 루프백에서 발급 → 그 키로 원격 세션이 생긴다(시험이 해시를 직접 두지 않는다), 원격에서 발급 · 풀기는 403, 답 말고는 키가 어디에도 안 남는다.

### 7차 구현 메모
테스트: `crates/server/tests/round14/`. 코드: `crates/server/src/access_http.rs`, 조립은 `app/parts.rs`의 `open_gate`.

- 경로: `POST /api/access/key`(그 컴퓨터, 답 `{"access_key", "generation"}`, `no-store`) · `POST /api/access/unlock`(그 컴퓨터, 본문 `{"device": "<IP>"}`, 답 `{"unlocked": bool}`, IP가 아니면 400) · `GET /api/access/log`(세션, 기록 새것부터 200줄과 `locked` 기기 목록).
- `AccessKeys`는 관문을 연 뒤에야 얻으므로 경로는 빈 자리(`OnceLock`)를 쥐고 `serve` 뒤 채운다. 채우기 전 요청은 503.
- 잠금 알림(E2)은 5차에서 이미 이어져 있었다(`reach::LockNotices` → notify `AccessLock`, round11 시험). 확인만 했다.
- 설정 화면에 "접속 키" 칸: 만들기/바꾸기 단추(키는 답에서 한 번만 보이고 화면에 간직하지 않음), 잠긴 기기와 풀기 단추, 접속 기록.

### 7차 검토 참고 (다듬기 후보)
- `access_log`가 기록 전체를 읽고 200줄로 자른다(store에 최근 n줄 조회).
- 발급한 키가 다음 동작 · 새로 읽기 전까지 화면(DOM)에 남는다(일정 시간 뒤 지우기).
- 채우기 전 503 경로 시험이 없다.

## 8차 작업 (바깥 키 칸 등록 · 접속 키 다듬기)

사용자 말: "외부에서 가져와야 되는 키값들은 설정에 비밀값으로 넣을 수 있게 기능을 만들면 돼."

- 키 등록 경로(`/api/setup/keys` 그 컴퓨터 · `/api/remote/keys` 세션)에 `item` `dart` · `ecos` · `fred` · `backup_github_token`(공개 상수 `KEY_DART` 등 · `KEY_SLOTS`)을 더했다. 칸 이름은 `KeySlot::fields()`, 몸통 · 상한 · 공백 떼기 · 값 지우기 · 답(등록 여부뿐) · 시도 횟수는 기존 키와 같다. 저장은 `SecretStore::register_slot`.
- 확인: `KeyVerifier::verify_slot` — 자료 칸은 `pi_data::verify_slot`(팀 조립의 `TeamWiring.data` 주소), 토큰은 `pi_backup::verify_token`(3차 조립 `reach.backup.api_base`, 없으면 GitHub 기본 주소). 주소가 없는 쪽(팀 · 3차 조립 없이 띄움)은 확인하지 않아 저장되지 않는다(`Unreachable`). `KeyVerifier::new(Upstreams)`는 그대로 두고 `with_data` · `with_github`를 더했다(앞 차수 시험이 `Upstreams`를 글자 그대로 만든다).
- 칸별 상태: `GET /api/setup/slots`(세션) → `{"slots": [{"name", "registered"}]}`. **`GET /api/setup`에 넣지 않은 까닭**: 앞 차수 잠긴 시험(setup/mod.rs)이 그 답의 칸을 못 박아 둔다. 자료 키 · 토큰은 시작 조건이 아니다.
- 화면: 설정 화면 "바깥 키 (선택)" 칸과 `/keys` 화면에 칸마다 입력(password · new-password · spellcheck=false) · 등록 단추 · 등록 여부. 성공하면 입력을 비운다.
- `access_log`는 `Store::access_recent(200)`을 쓴다(전체를 읽지 않는다).
- 발급한 접속 키는 60초(`ACCESS_KEY_SHOW_MS`) 뒤 화면에서 지운다(다시 만들면 앞 타이머를 지운다).
- 접속 키 자리를 채우기 전 503: `access_http.rs` 안 단위 시험(관문을 연 뒤 바로 채워 HTTP로는 그 틈을 만들 수 없다).
- 시험: `tests/round15`(가짜 자료 · GitHub 서버, 가짜 값).

### 8차 검토 참고
- 옛 `item` `data`(`KeyKind::Data`, 확인할 곳 없음)는 그대로 둔다. 새 칸과 겹치므로 다음 차수에 화면에서 뺄지 정한다(물음).

### 9차 보강 (검토 되돌림 — 2026-11-21 조정자)

1. **도는 서버가 있을 때의 `access-key`** (보안, V41 · 결정 2026-11-16 8번): 세대와 세션은 도는 서버의 메모리에 있어서, 다른 프로세스가 저장소의 세대만 올리면 앞 세대 원격 세션 · 열린 WebSocket이 끊기지 않는다. 그래서 `access-key`는 먼저 **이 홈으로 도는 서버가 있는지** 본다: 설정의 여는 포트의 루프백(`127.0.0.1:<port>`)에 화면과 같은 경로(`/api/access/key`, 그 컴퓨터 전용 경로)로 요청해 그 서버가 키를 만들게 한다(세대 올리기 · 앞 세대 세션 끊기 · WebSocket 닫기가 그 서버 안에서 일어난다). 연결이 거부되면(도는 서버 없음) 지금처럼 직접 만든다. 응답이 우리 서버의 모양이 아니면(그 포트를 다른 프로그램이 씀) 키를 만들지 않고 오류와 안내(`--port`를 맞게 주거나 서버를 멈춘 뒤 다시)로 끝낸다. `--rotate` 없이 이미 키가 있으면 어느 길이든 거부. 안내 글 "앞 세대 키로 들어온 원격 연결은 끊깁니다"는 실제로 끊기는 길에서만 쓴다.
   - 시험: 같은 홈으로 `App`을 띄워 원격 세션(쿠키)과 WebSocket을 만든 뒤 `access_key(rotate)`를 부르면 옛 쿠키가 401이고 WebSocket이 닫히며, 새 키로 들어올 수 있다. 서버가 없을 때는 지금 시험 그대로. 그 포트가 다른 프로그램이면 키가 만들어지지 않는다(세대 그대로).
2. **서버를 띄우지 않는 명령은 보관 폴더를 만들거나 고치지 않는다**: `doctor` · `service …` · `restore` · `--version`은 `SecretStore::open`(폴더를 만들고 0700 · 0600으로 좁힌다)도 `Store::open`(스키마를 올린다)도 부르지 않는다. 지금은 `main.rs`의 `init_tracing`이 모든 명령에서 `SecretStore::open`을 불러, 실행 파일의 `doctor`가 진단 전에 폴더를 만들고 권한을 고쳐 버린다(진단 1번의 ✗가 나올 수 없다). 기록 가리기가 필요한 것은 `run`(과 직접 만드는 `access-key`)뿐이다. `doctor`의 저장소 열기는 **읽기 전용**(`SQLITE_OPEN_READ_ONLY`) + 짧은 busy_timeout으로 하고, 잠금에 걸린 것을 "깨졌다"로 알리지 않는다("다른 프로그램이 쓰는 중"으로).
   - 시험(실행 파일로): `doctor --home <0755 폴더>` → 종료 코드 1, 출력에 고치기(`chmod 700`), 폴더 권한은 0755 그대로. `doctor --home <없는 폴더>` → 폴더가 생기지 않는다. `service status --home <없는 폴더>`도 폴더를 만들지 않는다.
3. **Windows 기록**: `run`에 `--log-file <경로>`를 더한다(기록을 그 파일에 덧붙여 쓴다. 가리기는 그대로 거친다. 폴더가 없으면 만든다). Windows 예약 작업 정의는 인자에 `--log-file <home>\logs\server.log`를 싣는다(예약 작업은 표준 출력을 파일로 돌리지 못한다). macOS(`StandardOutPath` · `StandardErrorPath`) · Linux(journal)는 지금 그대로. 파일 돌려 쓰기(크기 상한)는 다음 차수 후보.
   - 시험: 운영체제마다 정의가 기록 자리를 가리킨다(macOS 두 경로, Windows `--log-file` 인자, Linux는 없음). `run --log-file`로 띄우면 그 파일에 기록이 생기고 비밀 글자가 없다.
4. 다음 차수 후보(이번에 하지 않음): systemd `%` · `$` 이스케이프, Windows 경로 끝 `\` 따옴표, 환경 변수로 준 `--bind` · `--port`가 정의에 안 실린다는 안내 한 줄, macOS에서 계속 죽는 서비스를 `status` · `doctor`가 알리기, 기록 파일 돌려 쓰기, `doctor`가 store · backup의 속 모양 대신 읽기 전용 손잡이를 쓰기, gate가 세션 확인 때 저장소 세대도 보게(방어 한 겹 더).

"쓰는 템플릿"을 고르는 규칙은 한 곳에 두고, 더 오래된 다른 템플릿으로 조용히 넘어가지 않는다.

## 11차 Vite 이전 (2026-11-23, 결정 1 · 결정 1 자리 조정)

화면을 손으로 쓴 HTML/JS에서 Vite + TypeScript 다중 페이지로 옮긴다. **동작과 경로는 지금 그대로** — 이 차수는 옮기기이고, 새 화면은 사무실 승인 카드(10c 14번) 하나뿐이다.

1. **프로젝트**: `crates/server/web/`가 Vite 프로젝트다(`package.json` · `package-lock.json` · `tsconfig.json` · `vite.config.ts` · `src/` · 페이지 HTML). `node_modules/`는 커밋하지 않고, 빌드 결과 `crates/server/web/dist/`는 커밋한다. `package.json`에 스크립트 `typecheck`(`tsc --noEmit`) · `test`(`vitest run`) · `build`(`vite build`)를 둔다(verify.sh 3w가 부른다). 의존은 판을 고정한다: `vite` · `typescript` · `vitest` · `three`(지금 vendor와 같은 계열) · 화면 시험에 DOM이 필요하면 `jsdom` 하나. 그 밖의 의존은 더하지 않는다(더해야 하면 멈추고 묻는다). 빌드는 같은 소스에서 늘 같은 결과(이름의 해시는 내용 해시)여야 한다.
2. **페이지(옮길 것)**: 설정(`crates/server/web/index.html` → `/`), 키(`keys.html` → `/keys`), 사무실(`crates/office/web/office/*` → `/office/`), 폰(`crates/notify/web/phone/*` → `/phone/`, `sw.js` · `manifest.webmanifest` · 아이콘 포함. 서비스 워커는 해시 없는 고정 이름 · 지금과 같은 범위). 지금 화면의 JS를 TS로 옮기되 **하는 일 · 보내는 요청 · 화면 글은 같게**. 키 칸 규칙(password · new-password · spellcheck=false · 성공하면 비움 · 값을 다시 보이지 않음)과 바깥 CDN 없음, 브라우저 저장소에 비밀 없음은 그대로. `three`는 npm에서, 라이선스 글은 dist에 함께 둔다.
3. **내주기**: server가 `dist`를 실행 파일에 넣어(빌드 스크립트로 파일 표를 만들거나 `include_bytes!` 표 — 바깥 의존을 더하지 않는다) 지금과 같은 경로 · 같은 머리(CSP · 내용 형식 · 캐시)로 내준다. 해시 붙은 파일은 오래 캐시해도 되고, HTML · `sw.js` · manifest는 지금처럼. server는 더는 `pi_office::web_assets()` · `pi_notify::phone_asset(s)`와 `crates/server/web/*.html` 직접 include를 쓰지 않는다. (office · notify 크레이트 안의 옛 `web/` · `web_assets`를 지우는 것은 그 모듈의 다음 차수 — 이 차수는 server만 고친다.)
4. **사무실 승인 카드** (10c 14번 화면): 사무실 페이지가 `office.approval` 이벤트(번호 · 가린 요약 · 지문 앞 6자 · 상태)로 카드를 그리고, 승인/거절은 폰과 같은 `/api/approvals/{id}/approve|reject` 경로 · 같은 지문 대조로 보낸다. 상태가 pending이 아니게 되면 카드를 닫는다. 요약은 글(textContent)로만 넣는다(HTML로 넣지 않는다).
5. **시험**: 화면 시험은 `crates/server/tests/web/*.test.ts`(vitest)에 둔다 — 승인 카드 그리기 · 닫기 · 요약이 HTML로 해석되지 않음, 키 칸 규칙, 화면이 부르는 경로 목록 같은 순수 논리. Rust 쪽은 실행 파일(또는 `App`)로 각 페이지 경로가 200 · 맞는 내용 형식 · CSP를 주는지, dist의 모든 파일이 경로로 닿는지, 옛 페이지 경로가 그대로인지. **잠긴 옛 시험이 HTML 글자를 직접 보는 경우**(예: round18 `screens.rs`) 그 내용이 JS 번들로 옮겨 가 깨지면, N1이 같은 뜻을 dist 안에서 찾도록만 고치고 고친 시험마다 까닭을 보고한다(뜻을 바꾸지 않는다).
6. 이 차수에서 하지 않는 것: 화면 모양 새로 그리기, React 같은 틀, office · notify 크레이트 고치기.

### 11차 보강 (검토 되돌림 — 2026-11-23 조정자)
1. **승인 번호는 글자다**: 서버의 `office.approval` 이벤트 `number`는 `ApprovalNumber`(무작위 hex 글자)다. 화면 시험(`tests/web/office-approval.test.ts`)이 숫자를 쓰고 글자를 "틀린 몸통"으로 버리게 해서, 실제 카드가 한 장도 그려지지 않는다. 시험을 글자 번호로 고치고(빈 글자 · 글자가 아닌 것은 버림), 화면도 글자로 받는다. 경로는 `encodeURIComponent` 그대로.
2. **package-lock 다시 만들기**: 항목 55개에 `resolved` · `integrity`가 없다. 같은 판 그대로 lock을 다시 만들어 모든 항목에 해시가 있게 한다(N1).
3. **wss 머리**: CSP `connect-src`에 `ws://<Host>`와 함께 `wss://<Host>`를 적는다(https 원격, 오래된 브라우저). 같은 Host 검사.
4. **dist의 숨은 파일**: build.rs는 이름이 `.`으로 시작하는 파일(`.DS_Store` 등)을 넣지 않는다.
   - (N2 뒤 조정자) 3번은 이 걸음에서 하지 않는다: 잠긴 round20 `pages.rs`가 바깥 원천으로 `ws://<Host>`만 허용한다. 다음 차수에 시험과 함께 한다(지금은 CSP3의 `'self'`가 wss를 덮는다).
5. 참고(다음 차수 후보): 흔들리는 시험 둘 — round9 `loss` 하루 손실(AnomalyHalt), round10 `day::아무것도_누르지_않아도_하루_시작과_논의와_마감_기록이_남는다`(Resting/Operating, 2026-11-24 한 번), wss 머리(위), 승인 단추를 보내는 동안 막기, `submitKeyFields`를 화면에 쓰거나 지우기(키 칸 비우는 때를 한 규칙으로), three 형 정의, minify.

## 12차 옛 화면 시험 옮기기 (2026-11-24, office · notify 옛 화면 정리와 함께)

office · notify 크레이트의 옛 화면 시험을 지우면서 화면 쪽 동작을 보는 시험이 빠진다. 같은 뜻을 server 화면 시험으로 옮긴다(동작은 이미 `crates/server/web`에 있다 — 옮기기만, 동작을 새로 만들지 않는다). notify의 `web/` 폴더는 이 차수가 끝난 뒤에 지운다.

1. **다른 크레이트 파일을 읽지 않는다**: round20 `dist.rs`의 서비스 워커 · manifest · 아이콘 시험이 `../notify/web/phone`의 파일과 바이트를 비교한다. notify 폴더를 지우면 깨지므로, 비교 대신 manifest 모양(아래 4)과 아이콘이 PNG이고 192 · 512 크기인지로 본다. server 시험은 다른 크레이트 폴더를 읽지 않는다.
2. **사무실 지도** (`public/office/office-map.json`, 옛 office `web_assets` 시험): 여섯 담당 모두 책상과 침대가 있고 둘은 다른 칸, 책상끼리 · 침대끼리 겹치지 않음, 방 이름이 서로 다름, 모르는 담당 없음 · 정확히 여섯, 논의 탁자 자리 6개 이상 · 서로 겹치지 않고 책상 · 침대와 다른 칸.
3. **응답 목록 정리** (C5, 옛 `web_prune`): 화면이 밀려난 줄을 버릴 때 끝난 응답(complete · failed)은 응답 표에서도 지우고, 오는 중인 응답은 남긴다. 시험하기 쉽게 `office/main.ts`의 정리 함수를 따로 모듈로 뺄 수 있다(동작 같게).
4. **폰** (옛 notify `phone` 시험):
   - 앱이 푸시를 구독한다(`pushManager.subscribe`, `applicationServerKey`, `userVisibleOnly: true`).
   - 서비스 워커가 푸시 본문 JSON의 title · body로 `showNotification`을 부르고, 알림을 누르면 폰 화면을 연다.
   - manifest: name · id · scope · start_url이 비어 있지 않음, `display: standalone`, 192 · 512 아이콘, 아이콘 src가 묶음 안.
   - 폰 승인 카드 모양(`data-card="approval"`, 승인 · 거절 단추, 코드 칸 `maxlength=6` · `inputmode=numeric`, `data-approval-id`, `data-fingerprint`)과 결정 4번 방식(코드 칸 `readonly`, `one-time-code` · `pattern` 없음, 6자리 입력을 강제하지 않고 칸 값을 읽지 않음, 지문 앞 6자리를 보이고 카드의 지문을 그대로 보냄).
   - 폰 화면 요소: 알림 목록 `id="notice-list"`, "3D 사무실" 단추 `data-action="open-office"`, viewport 메타.
   - 하루 정리가 한 구역(`id="daily-summary"`) 안에 한 일 · 손익 · 복기(`data-part` done · pnl · review).
   - 폰 묶음에 three가 없다(결정 26).

## 14차 손실 기준 저장 순서 (2026-11-24 조정자, 13차 N3 참고 — 안전)

`books()`는 `marks` 잠금 안에서 저장할 손실 기준을 꺼내고(`take_payload`) 잠금을 푼 뒤에 저장한다(`save_basis`). 장부 셈 둘이 동시에 최고 평가액을 올리면 낮은 최고를 담은 기록이 나중에 저장될 수 있고, 다시 켜면 최고 평가액이 낮게 되살아나 **최대 낙폭 판단이 느슨해진다**(예전부터 있던 문제).

1. 저장되는 손실 기준이 뒤로 가지 않게 한다: 저장을 같은 순서로 줄 세우거나(저장 전용 잠금 안에서 꺼내기와 저장을 함께), 되읽을 때 통화별 최고 평가액을 저장된 기록들의 `max`로 합친다 — 둘 중 단순하고 확실한 쪽. 그날 시작 평가액은 그날의 첫 기준이 이긴다(하루 시작 경로가 정한 값).
2. 시험: 장부 셈 둘이 동시에 최고를 올리는 순서를 만들 수 있으면 그 순서에서도 다시 켠 뒤 최고 평가액이 둘 가운데 높은 값이다(src 안 단위 시험 가능 — 13차 books_race처럼, 지시서에 이름을 적는다).

## 16차 남은 후보 — 안전 (2026-11-24 조정자, 결정 12 · 사용자 "다음 이어서 작업해")

10b · 10c 검토 참고에 남은 server 쪽 안전 후보. exec 9차의 `Executor::forget_pending_sell`을 쓴다.

1. **전체 정지가 되면 팀장 팔기 대기를 지운다**: 투자 팀이 전체 정지가 되는 순간(최대 손실 · 그 밖의 전체 정지 길 모두), 실행기에 남은 다시 내기 대기 가운데 목적이 팀장 팔기(`TeamExit`)인 것을 `forget_pending_sell`로 지우고, 매매마다 방 기록에 "전체 정지로 팀장 팔기 다시 내기를 거둠"을 한 줄 남긴다. 손절 · 청산 대기는 남겨 지금처럼 계속 다시 낸다(E34). 익절 대기도 남긴다(정지와 무관하게 이익을 지키는 매도). 다시 시작(사용자 승인) 뒤에 정지 전 팀장 판단이 저절로 나가지 않아야 한다.
2. **이상이 풀린 뒤 장이 열렸을 때만 운용 중으로**: `watch.rs` `recovered()`는 그날 계획이 매매면 바로 `start_trading`한다. 장이 열려 있지 않으면(장 밖 · 휴장) 쉬는 중으로 두고, 다음 장 시작에 하루 흐름이 운용 중으로 옮기게 한다(지금 하루 시작 경로와 같은 판단).
3. **하루 AI 호출 상한 (설정, 기본 꺼짐)**: 설정에 "하루 AI 호출 상한"(정수, 비우면 상한 없음 — 기본은 비움이라 스펙 동작 그대로)을 둔다. 켜져 있으면 server가 그날(한국 시각 자정 기준) 팀 논의 · 깨우기로 AI를 부른 횟수를 세고, 상한에 닿으면 그날 남은 논의 · 깨우기를 쉬고 사용자에게 한 번 알린다("오늘 AI 호출 상한에 닿아 논의를 쉽니다"). 손절 · 청산 · 이상 감지 · 한도 판단은 AI를 부르지 않으므로 그대로 돈다. 횟수는 다시 켜도 그날 안에서는 이어진다(저장).

## 24차 시연 모드에서 팀이 실제로 돈다 (2026-11-25 조정자, 결정 17 — e2e 준비 중 발견)

근거: `docs/product/stock-team/additions.md` R2-3 · D14 · C33 · E56 · N19 · V54 · T35(차수 표 1번).
지금 시연용 가짜 증권사(`src/demo.rs`)는 달력을 정하지 않아 늘 휴장이고, 깨우기 엔진의 첫 tick이 "증권사 서버가 점검 중이거나 장애입니다 (HTTP 503)"로 실패한다. 그래서 시연 모드에서는 팀이 하루를 시작하지 않고 논의가 한 번도 열리지 않는다.

1. **시연 달력**: 시연 달력은 **실행 파일의 `--demo` 조립에서만 켠다** — 시연 어댑터의 기본(달력 없음)은 그대로 두고 켜는 길을 더한다(기존 시험이 쓰는 시연 어댑터 동작은 바뀌지 않는다). 켜면 시연 어댑터가 달력을 낸다 — 매일이 거래일이고 그 시장 시간대(kr · us)의 00:05~23:55가 정규장이다(N19). 자정 앞뒤 10분은 장 밖이라 하루 마감 · 하루 정리 · 복기가 매일 돈다. 실제 모드의 달력은 그대로다(시연 달력은 시연 어댑터 안에만 있다, E56).
2. **시연에서 하루가 돈다**: 시연 모드로 켜면 깨우기 엔진 첫 tick이 성공하고, 장 시간이면 팀이 하루를 시작한다(하루 판단 논의 → `office.talk` topic `day`). 시연 시세가 흘러 조건이 걸리거나 시연용 가짜 공시가 오면 종목 논의가 열린다.
3. **시연용 일감**: 시연 모드에서 사무실이 비어 보이지 않게, 시연 어댑터가 가짜 공시를 띄엄띄엄 낸다(기본 3분에 한 건, 지켜보는 종목을 돌아가며. 간격은 조립 값으로 시험이 줄인다). 가짜 공시는 "시연"이라고 적힌 제목 · 본문이고 실제 출처 주소를 쓰지 않는다.
4. **바깥으로 나가지 않는다**: 시연 모드는 모의계좌(pi-paper)와 시연용 가짜 AI만 쓴다. 실제 증권사 · AI · DART · 네이버로 나가는 요청을 만들지 않는다(키가 등록돼 있어도). 시작 글에 "시연 모드: 가짜 시세 · 가짜 AI · 모의계좌"를 남긴다.

- 원본 동작 근거: 원본에 없음 — additions.md D14 · C33 · E56, 스펙 F1, 결정 17.
- 시험으로 확인할 것(V54): 시연 조립으로 켜면 주말 · 밤 시각에도(자정 앞뒤 10분 빼고) 첫 tick이 성공 / 장 시간에 하루 시작 이벤트와 하루 판단 `office.talk`가 나온다 / 가짜 공시 간격을 줄이면 종목 논의가 열리고 담당 글 `office.talk`가 나온다 / 자정 앞뒤 10분에는 장 밖 / 로컬 가짜 서버로 세운 "실제" 주소들에 온 요청이 0건 / 실제 모드 달력은 그대로(시연 달력이 섞이지 않음).

## 25차 사무실 다듬기 — 순한 카메라 · 읽히는 판단 글 · 시연의 속도 (2026-11-25 조정자, 결정 18 · 24차 화면 확인)

24차를 실제 서버(시연 모드)로 보니 세 가지가 어색하다.

1. **발언자 카메라를 순하게**(결정 18 — 사용자 "카메라가 너무 돌아가는데? 굳이 카메라를 너무 확대할 필요 없을 듯"): 23차 7번 (나)를 고친다.
   - **돌지 않는다**: 발언자 샷에서도 보는 방향(방위각)과 고도는 탁자 샷 그대로다(원본의 고도 15° · 발언자 정면으로 돌기를 쓰지 않는다).
   - **조금만 다가간다**: 보는 중심을 탁자 가운데에서 발언자 쪽으로 절반만 옮기고, 거리는 탁자 샷 거리의 0.8배까지만. 여섯 담당이 계속 화면 안에 있다.
   - **느리게 · 덜 오간다**: 전환 1.2초(ease-in-out). 마지막 말 뒤 유지는 4초(발언이 이어지는 동안 탁자 샷으로 돌아가지 않는다), 최소 머무름 2초는 그대로. 다른 담당이 말하면 탁자 샷을 거치지 않고 그 담당 쪽으로 옮긴다.
   - 단추 · 손으로 움직이면 꺼짐은 그대로.
2. **판단 글을 사람이 읽게**: 지금 팀장의 하루 판단 · 종목 판단 글이 화면(팀 탭 · 말풍선 · 자막)에 날 JSON(`{"plan":"trade"}` · `{"decision":"buy",…}`)으로 온다. `office.talk`의 `text`는 사람이 읽는 문장으로 낸다(방 로그의 원문은 그대로 둔다).
   - 하루 판단: 운용이면 "오늘은 운용합니다.", 쉬면 "오늘은 쉽니다 — {이유}".
   - 종목 판단: 사기 · 팔기는 "사기로 정했습니다 — 진입 71,100 · 손절 67,545 · 목표 78,210. {가설}" 모양(금액은 그 시장 돈 모양으로, 가설 · 계기 글은 가린 것), 지켜보기는 "지켜보기로 했습니다 — {이유}".
   - JSON으로 읽히지 않는 팀장 글은 원문 그대로 둔다(자르기 500자는 그대로).
3. **시연의 속도**: 시연용 가짜 AI(`team/demo_ai.rs`)는 지금 즉시 답해서 논의가 한순간에 끝나고, 담당들이 미팅룸에 모여 차례로 말하는 모습이 보이지 않는다. 실행 파일의 `--demo` 조립에서만 가짜 AI의 답마다 뜸(기본 2.5초, 조립 값)을 둔다. 시험이 쓰는 가짜 AI의 기본(뜸 없음)은 그대로다.
4. 화면에서 종목 표시가 `day`인 줄은 "하루 판단"으로 보인다(지금 그대로)는 것과, 띄울 때마다 남는 `team-open` 영수증 중단 경고 한 줄(24차 N2 참고)을 없앤다 — 첫 tick 뒤 엔진을 다시 시작하지 않게 조립 순서를 고친다(영수증은 처음부터 ok로 끝난다).

### 31차 고침 (2026-11-25 조정자, 결정 22 — 결정 21과 위 "31차 대조 보강"을 거둔다)

알림음 설정(1번 (바))은 브라우저 저장소가 아니라 **서버**가 둔다. V46 · D11 · N8("화면은 브라우저 저장소 · 쿠키 · 주소에 값을 남기지 않는다")은 그대로 지킨다.

1. `GET /api/setup/sound` → `{"enabled": true|false}`(기본 켜짐). `POST /api/setup/sound` `{"enabled": bool}` → 같은 모양. 관문은 `/api/setup`의 다른 쓰기와 같다(세션 · 원격 401 · Origin). `enabled`가 참 · 거짓이 아니면 400이고 저장하지 않는다.
2. 저장은 홈 폴더의 설정 파일에 한다(하루 AI 상한을 두는 방식과 같게 — 저장소 판을 올리지 않는다). 서버를 다시 만들어도 남는다. 파일을 읽지 못하면 기본(켜짐)으로 본다.
3. 화면: `web/src/ui/sound-pref.ts`는 브라우저 저장소를 쓰지 않는다 — 서버에서 읽고 서버에 쓴다(읽기 · 쓰기 실패에도 던지지 않고 기본 켜짐). 설정 화면의 알림음 칸은 읽은 값을 보이고, 바꾸면 보낸 뒤 서버의 답으로 맞춘다(실패면 되돌리고 오류 줄).
4. 화면 코드 어디에도 `localStorage` 글자가 없다(`key-fields`의 예외를 되돌린다).

## 32차 내 캐릭터 · 방향키 이동 · 카메라 따라가기 · 다가가 말 걸기 (2026-11-25 조정자, 결정 17 — 사용자 "내 캐릭터도 있으면 좋을 듯. 키보드로 움직일 수 있게" · "키보드는 방향키로" · "진짜 게임처럼")

근거: `docs/product/stock-team/additions.md` R5-4 · F10 기본 흐름 1~7 · 2a · 2b · 2c · 2d · 3a · M8 · C17 · E40 · E41 · E59 · V56 · T24(차수 표 13번), 화면 표의 "사무실 · 내 캐릭터 / 이동 / 카메라" 줄.
지금 사무실에는 담당 여섯만 있고 사용자는 카메라로만 본다. 저장소에는 내 캐릭터 자리(store 19차 `player_profile`)가 이미 있다.

1. **내 캐릭터 API**(C17): `GET /api/office/me` → `{"name","look","x","y","dir"}`(없으면 기본 — 이름 "나", 외형 기본, 입구 자리). `POST /api/office/me` `{"name"?, "look"?}`(이름 · 외형의 한도는 store가 정한 그대로 — `PLAYER_NAME_MAX_CHARS` 등. server는 한도를 새로 정하지 않고 store의 거부를 400으로 옮긴다). `POST /api/office/me/position` `{"x","y","dir"}`(사무실 칸 범위 안, 방향 넷 가운데 하나). 관문은 사무실의 다른 API와 같다(세션 · 원격 401 · Origin). 저장은 store의 `player_profile`에 한다. 범위를 벗어난 값은 400(E3)이고 저장하지 않는다.
2. **자리 저장은 띄엄띄엄**: 화면은 걷는 동안 매 칸마다 보내지 않는다 — 멈춘 뒤 1초에 한 번, 그리고 화면을 떠날 때 한 번 보낸다(서버에 일을 주지 않게). 저장이 실패해도 걷기는 그대로다(F10 "실패 시 보장").
3. **그리기**: 내 캐릭터는 담당과 같은 방식으로 그리되 발 아래 이름표가 녹색(원본의 내 이름표 색)이다. 사무실이 열리면 저장된 자리(없으면 입구)에 선다.
4. **방향키 이동**(원본 DeskRPG와 같게): 방향키 넷만 쓴다(WASD 없음 — 결정 17). 누르고 있으면 계속 걷고, 두 키를 같이 누르면 대각선이며 속도를 보정한다(대각선이 더 빠르지 않게). 벽 · 가구 · 담당이 있는 칸으로는 들어가지 못하고 그 앞에서 멈춘다(E40). 글 칸 · 고르기 칸에 초점이 있거나 한글 조합 중이면 방향키는 캐릭터를 움직이지 않는다(E41). 방향키가 화면을 스크롤하지 않게 한다(사무실 층에 초점이 있을 때만).
5. **바닥 누르기**: 바닥을 누르면 그 칸까지 길을 찾아(막힌 칸을 피해) 걸어간다. 길이 없으면 움직이지 않는다. 끌기(카메라 이동)는 누르기로 치지 않는다(움직인 거리 문턱). 걷는 중 방향키를 누르면 길 따라가기를 버리고 방향키를 따른다. 멀리 있는 담당을 누르면 그 담당 옆 빈 칸까지 걸어가 대화를 연다(2b).
6. **카메라 따라가기**: 기본은 내 캐릭터를 따라간다(부드럽게). 사용자가 끌기 · 돌리기 · 확대를 하면 따라가기가 풀리고, 도구 줄의 "따라가기"로 다시 켠다. 도구 줄 8개(전체 보기 · 왼쪽 돌리기 · 오른쪽 돌리기 · 입체 · 위에서 · 따라가기 · + · −)와 오른쪽 아래 조작 안내("방향키 이동 · / 대화 · 끌기 화면 이동")를 둔다. 회의 발언자 카메라(결정 18)는 따라가기가 켜져 있으면 끼어들지 않는다(내 캐릭터가 우선) — 따라가기가 꺼져 있을 때만 지금처럼 돈다.
7. **다가가 말 걸기**: 담당과 2칸 안이면 화면 아래에 "○○을(를) 클릭하거나 /를 눌러 대화"가 보인다(조사는 받침에 맞춘다). `/`나 그 담당을 누르면 지금의 1:1 대화가 열린다. 2칸 안에 둘 이상이면 `/`에 "누구와 대화?" 목록이 뜬다(3a). 대화 중인 담당에게서 2칸 넘게 멀어지면 대화가 닫힌다(7). 글 칸에 초점이 있으면 `/`는 글자다.
8. **두 화면**(E59): 화면마다 내 캐릭터가 따로 움직인다(서로 실시간으로 맞추지 않는다). 마지막으로 저장한 쪽이 남는다.
9. **가볍게**: 새 npm 의존성 없음. 길 찾기는 사무실 칸 격자에서 너비 우선(또는 A*)으로 직접 쓴다. 관리 화면 묶음에 사무실 코드가 실리지 않는다(지금 상한 시험 그대로).

## 33차 멘션 · 전체 공지 · 담당 부르기 (2026-11-25 조정자, 결정 17 — 사용자 "채팅에서 멘션 가능하게" · "팀방에서는 전체 공지사항을 전달할 수 있게")

근거: `docs/product/stock-team/additions.md` R5-6~8 · R17 · F10 대안 4a~4e · 7a · F11 · C18 · C19 · C20 · E43~E48 · N10 · V58~V60 · V71~V74 · T27(차수 표 14번).
office 크레이트에는 이미 있다(office 5 · 6차): 멘션 읽기(`parse_mentions`) · 팀 방 글(`post_team`) · 답 잇기(`complete_with_relay`) · 공지(`post_notice`, `office.notice` · `office.notice_ack`) · 부르기 단계(`summon` — called → waiting → returning → idle, 10초 · 30초). store에는 공지 · 확인(`notices` · `notice_acks`)이 있다(store 19차). agent에는 공지를 논의에 넘기는 길(`with_notices`)이 있다(agent 11차). **server가 이것들을 API와 화면에 잇지 않았다** — 이 차수가 잇는다.

1. **멘션해서 말하기**(C18): `POST /api/office/chat`이 `{"room": "team", "text", "sourceMessageId"}`를 받는다(`agent`를 주면 지금처럼 그 담당 하나 — 그대로). 글 속 `@[이름]`으로 멘션된 담당만 답한다(여럿이면 차례로). 성공 `{"responders": [...], "responses": [...]}`. 멘션이 없으면 아무도 답하지 않고 `{"responders": [], "hint": "no_mention"}`(4b). 멘션한 이름이 담당 가운데 없으면 보낸 사람에게만 "지목한 상대가 이 방에 없어 아무도 답하지 않았습니다."(4d · E43). 하루 AI 상한 · 논의 중 등 기존 거절은 그대로다(E44는 설계서대로).
2. **멘션 걸어오기**: 멘션된 담당은 답을 쓰기 시작하는 순간 `office.summon`(`reason: "mention"`, `phase: "called"`)으로 내 곁으로 온다. 사용자가 팀 방을 보는 동안 곁에 남고, 다른 방으로 바꾸면(화면이 `POST /api/office/summon/view {"room"}`로 알림) 바로 돌아간다. 1:1 대화는 열리지 않는다(답은 채팅 패널과 머리 위 말풍선).
3. **전체 공지**(C19 · F11): `POST /api/office/notice` `{"text", "sourceMessageId"}` → `{"notice", "acks": [{"agent","state"}]}`. 담당 여섯이 차례로 짧게 확인 답을 한다(`office.chat`에 `"notice": 번호`, 담당별 `office.notice_ack`). `GET /api/office/notices?limit=`로 지난 공지와 확인 상태를 읽는다. 공지는 그 뒤 열리는 논의에 자료로 넘어간다(결정 19: 논의를 열기 전까지 보낸 공지만 — 보낸 시각이 판단 시각보다 늦지 않게). 같은 `sourceMessageId`를 다시 보내면 한 번만 처리한다. 실패는 E45 · E46대로(하루 상한이면 `"limit"` 상태로 남고 공지 자체는 저장된다).
4. **담당 부르기**(C20): `POST /api/office/summon {"agent"}` → `{"agent","phase":"called"}`. 화면이 걸어오기를 그리고 도착하면 `POST /api/office/summon/arrived`로 알린다(→ waiting). 대화가 10초 없으면 돌아간다(returning → idle). 30초 안에 도착 알림이 없으면 자리로(N10). 모르는 담당 400 `unknown_agent`, 회의 중 409 `meeting_reserved`(E47), E48은 설계서대로. 시간은 office 크레이트의 시계로 재고 server는 주기적으로 그 시계를 굴린다(깨우기 엔진과 따로, 가볍게).
5. **화면 — 멘션 칩**: 팀 방 글 칸에서 `@`를 치면 담당 목록이 뜨고(방향키 · Enter · 누르기로 고름, Esc로 닫음) 고르면 `@이름` 칩이 글에 들어간다. 보낼 때 `@[이름]`으로 바뀌어 간다(이름 속 `\` `[` `]`는 `\`로 가림). 칩은 한 번의 지우기로 통째로 지워진다. 한글 조합 중에도 깨지지 않는다. 멘션 없이 보내면 "@로 담당을 부르거나 공지로 보내세요" 안내(4b2).
6. **화면 — 공지**: 팀 방에 "공지" 단추. 누르면 글 칸이 공지 모드가 되고(표시가 보인다) 보내면 공지로 간다. 공지는 채팅에 다른 모양(공지 띠)으로 보이고 그 아래 담당별 확인(✓ 답함 · 기다림 · 상한 · 실패)이 붙는다. 사무실에 들어오면 지난 공지를 읽어 채운다.
7. **화면 — 부르기**: 담당 목록(담당 탭 · 외형 목록)에 "부르기" 단추. 누르면 그 담당이 자리에서 내 곁 빈 칸까지 걸어오고(32차 길 찾기) 나를 보고 선다. 도착하면 1:1 대화가 열린다(4c4). 멘션으로 온 담당은 대화를 열지 않는다. 회의 중이면 "회의 중이라 부를 수 없습니다" 안내(E47). `office.summon` 이벤트로 단계가 바뀌면 그대로 그린다(다른 화면에서 불러도 보인다).
8. 관문은 사무실의 다른 쓰기와 같다(세션 · 원격 401 · Origin). 글은 저장 · 이벤트 전에 가린다(기존 가림 규칙 그대로).

### 33차 시험 결함 고침 (2026-11-25 조정자, N2 보고)

`round35/mention.rs`의 두 시험(멘션 없음 → `no_mention`, 맞지 않는 이름 → `no_match`)은 "글을 보낸 뒤 AI 부름이 늘지 않는다"를 본다. 그런데 서버가 켜지며 깨우기 엔진의 첫 tick이 뒤에서 하루 판단을 돌리고, 그 AI 부름 1건이 기준 수를 잡은 직후에 들어와 늘 실패한다. 멘션과 무관한 부름이다. 단언의 뜻(멘션이 없거나 맞지 않으면 담당의 AI를 부르지 않는다)은 그대로 두고, 기준 수를 **시작 때의 부름이 잦아든 뒤에** 잡게만 고친다. 구현 · 계약은 바뀌지 않는다.

## 35차 업종표 · 금지 종목을 실제로 잇는다 — 시연에서 주문까지 간다 (2026-11-25 조정자, 34차 검토에서 발견)

근거: 결정 19번(처음 목록: "P5 · P8 · P12의 자료 — 1차는 설정 파일의 금지 종목과 업종표"), 스펙 R7-3 · F5(규칙 화면), `docs/product/principles.md` P5 · P8 · P12, additions.md D14 · C33(시연).
지금 `default_wiring`은 금지 종목 · 업종표를 **빈 채로** 준다. 설정 파일을 읽는 곳이 없다. 그래서 실제 모드든 시연 모드든 사는 주문이 모두 "P8 업종표에 없는 종목"으로 막혀, 팀이 사기로 정해도 주문 · 승인이 한 번도 생기지 않는다(34차 화면 확인). 결정 19번이 정한 것을 잇지 않은 빠진 구현이다.

1. **설정 파일**: 보관 폴더의 `rules-config.json` `{"banned": [{"market","symbol"}], "sectors": {"종목": "업종"}}`을 켤 때 읽어 주문 길(`TradingWiring::rules`)에 넣는다. 파일이 없으면 둘 다 빈 것이다(지금과 같다 — 모르는 종목은 여전히 막는다, P8). 파일이 깨졌으면 켜지지 않고 까닭을 말한다(조용히 빈 표로 돌아 규칙이 풀리거나 다 막히지 않게).
2. **읽기 · 고치기 API**: `GET /api/rules/config` → `{"banned": [...], "sectors": [{"symbol","sector"}]}`. `POST /api/rules/config`로 통째 바꾼다(같은 모양). 고치기는 **같은 컴퓨터에서만**(하루 AI 상한과 같은 관문 — 원격 세션은 403 `loopback_only`), 값 검사(종목 글자 · 업종 이름 길이 · 중복)에 걸리면 400이고 저장하지 않는다. 저장은 원자적으로(임시 파일 → 옮기기). 바꾼 값은 **바로** 주문 전 점검에 쓰인다(다시 켜지 않아도). 바꾼 일을 이벤트 · 기록에 남긴다(누가 언제 — 값 자체는 비밀이 아니다).
3. **규칙 화면**(`/rules/`): "금지 종목"과 "업종표" 묶음을 더한다 — 지금 값을 표로 보이고, 같은 컴퓨터면 줄을 더하고 지우고 저장할 수 있다(원격이면 보기만 · "이 컴퓨터에서만 바꿀 수 있습니다"). 지켜보는 종목 가운데 업종표에 없는 것이 있으면 "업종이 없어 살 수 없는 종목: …" 경고 줄을 보인다(진단 표에도 한 줄).
4. **시연**: 시연 조립은 시연 종목(지켜보는 종목 전부)에 시연용 업종("시연 업종 A" 식)을 넣어 준다 — 파일을 쓰지 않고 조립 값으로(E56: 시연 값이 실제 설정에 섞이지 않게). 시연 어댑터는 종목 상태(VI · 거래정지)를 "아님"으로 알려 P12에도 막히지 않는다. 그래서 **시연에서 팀이 사기로 정하면 주문 전 점검을 지나 주문(또는 승인 기다림)까지 간다**. 모의계좌(pi-paper)뿐이고 실제 증권사로는 나가지 않는다(AGENTS 6번).
5. **개선안 승인 이벤트**: 규칙 개선안의 승인 요청도 다른 승인과 같게 `office.approval`(agent `review`, state `waiting`)을 낸다(34차에서 화면이 `rule_proposal`을 받고 다시 읽어 메우던 것 — 그 메움은 남겨도 된다). 폰 알림은 지금 규칙 그대로(두 번 가지 않게).
6. 승인 답이 서버에서 실패(5xx)해도 화면은 대기 목록을 다시 읽어 ✋를 맞춘다.

- 원본 동작 근거: 원본에 없음(우리 규칙) — 결정 19번 · principles P5 · P8 · P12, 스펙 R7-3. 고치기를 같은 컴퓨터로 묶는 것은 하루 AI 상한(server 21차)과 같은 까닭(규칙을 푸는 일은 사용자가 직접).

## 37차 `price-inha setup` 마법사와 `open` (2026-11-26 조정자, 결정 24 — 사용자 "cli로 다른 컴퓨터에서 설치하고 세팅까지 도와주는 것" · "CLI는 러스트로")

근거: `docs/research/onboarding-messenger.md` 2.1 · 2.2 · 5장 (가) · (나), `docs/research/install-and-cli.md`, 결정 24. 앞선 결정 "setup 명령을 두지 않는다"는 결정 24로 거뒀다.
지금 `price-inha`의 하위 명령은 run · doctor · restore · service · access-key 등이고, 처음 세팅은 브라우저 설정 화면에서만 한다. 다른 컴퓨터에 깔고 터미널만으로 세팅을 끝낼 길이 없다.

1. **`price-inha setup [구역]`**(터미널 전용 마법사, Rust): 구역은 `ai` · `broker` · `symbols` · `service` · `open`(이번 차수), 구역을 주지 않으면 차례로 모두. 메신저 구역은 채널 차수에서 더한다(이번에는 "메신저는 나중에 `price-inha setup messenger`로" 한 줄만).
2. **저장 길은 하나**: 마법사는 값을 직접 파일에 쓰지 않는다 — **도는 서버의 같은 컴퓨터(루프백) 설정 경로를 그대로 부른다**(`access-key`가 하는 방식). 그래서 등록 전 확인 · 시도 제한 · 원자적 쓰기 · 가림 규칙이 화면과 한 벌이다. 도는 서버가 없으면 "지금 띄울까요?"를 묻고(기본 예) 뒤에서 띄운 뒤 이어 간다(마법사가 띄운 서버는 서비스로 등록하지 않으면 마법사가 끝날 때 끈다).
3. **0단계**: 보관 폴더 위치 · 권한을 확인해 보여 준다. 이미 설정된 항목은 "있음"으로 보이고 "다시 할 구역 고르기"를 묻는다(원본 Hermes의 다시 실행).
4. **AI 연결 구역**: 찾기 — `claude` 실행 파일이 PATH에 있는가 → 있으면 지금의 확인 길(버전 · 로그인됨)로 본다. 결과를 보여 주고 고르게 한다: [Claude CLI(로그인됨)] / [Claude CLI는 있지만 로그인 안 됨 → "다른 창에서 `claude auth login`을 실행한 뒤 Enter"를 안내하고 다시 확인] / [API 키 입력(글자가 보이지 않는 입력)] / [건너뛰기]. 고른 것만 등록 전 확인을 거쳐 저장한다. **다른 프로그램의 토큰 파일을 읽지 않는다. OAuth를 직접 하지 않는다**(결정 24). 환경에 `ANTHROPIC_API_KEY`가 있는데 CLI 방식을 고르면 "CLI도 API 키로 과금될 수 있다" 경고 한 줄.
5. **증권 키 구역**: 모의계좌라 필요한 칸만 묻는다(`/keys` 화면의 칸과 같게). 보이지 않는 입력 → 등록 전 확인. 빈 입력은 건너뛰기.
6. **종목 구역**: 지켜볼 종목을 쉼표로 받는다(지금 `/api/setup/symbols`의 검사 그대로). 업종표에 없는 종목이면 "규칙 화면에서 업종을 넣어야 살 수 있다"를 알려 준다(35차).
7. **서비스 구역**: "계속 켜 둘까요?"(기본 예) → 예면 지금의 `service install`과 같은 일. 아니오면 "`price-inha run`으로 켠다" 안내.
8. **열기**: 끝에 대시보드 주소를 보여 주고 브라우저로 연다(주소에 비밀값 없음). `price-inha open [화면]`은 그 일만 따로 한다 — 도는 서버 주소를 찾아 `/`(기본) · `office` · `account` · `templates` · `rules` · `history`를 연다. 도는 서버가 없으면 까닭과 "`price-inha run`"을 말하고 종료 코드 1.
9. **비대화형**: 표준 입력이 터미널이 아니면 마법사를 돌리지 않고 "터미널에서 `price-inha setup`을 실행하거나 브라우저 설정 화면을 여세요"를 말하고 종료 코드 2(원본 Hermes). 다만 시험과 자동 설치를 위해 답을 표준 입력으로 흘려 넣는 숨은 길(`--stdin-answers`)을 둔다 — 비밀값은 인자로 받지 않는다(프로세스 목록에 남지 않게).
10. **끝 요약**: 구역마다 "됨 · 건너뜀 · 실패(까닭)"를 표로 보이고, 남은 일은 `price-inha doctor`를 안내한다. 비밀값은 화면 · 기록 어디에도 다시 찍지 않는다.
11. 인자 없이 `price-inha`만 치면: 설정이 하나도 없으면 "`price-inha setup`을 실행할까요?"를 묻고(터미널일 때만), 있으면 지금처럼 도움말.
